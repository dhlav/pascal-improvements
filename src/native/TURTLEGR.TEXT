;---------------------------------------------------
; TURTLEGRAPHICS' seven native procedures,
; SYSTEM.LIBRARY segment 20: the hi-res primitives
; and the line drawer, the clipper, MOVEABS, MOVEREL,
; FILLIT, SCREENBIT and DRAWBLOCK.
;
; The other twenty-four procedures of the unit are
; Pascal and are in
; src/pascal/units/1.3/TURTLEGRAPHICS.text.
;
; Reconstructed from the 1.3 binary. Assemble with
; Apple's own SYSTEM.ASSMBLER: it generates the
; relocation tables (finding 44), and those are part
; of what has to match. All seven come out byte for
; byte, relocation tables included.
;
; The order below is the order the seven sit in the
; shipped segment, which is the order they were
; assembled in and not the order the unit declares
; them (finding 96c).
;
; What is ours and what is Apple's:
;   * every label name and every comment is ours;
;   * the six entry points HIRES exports, and the one
;     CLIP exports, are Apple's structure -- the
;     binary has a segment-relative relocation for
;     each, which is a .DEF/.REF pair and nothing
;     else (finding 98a);
;   * labels that were L<nnnn> (proc-relative offsets)
;     are renamed on the improvements fork to unique
;     role names (all Lxxxx cleared).
;
; Zero page. A native procedure runs inside the
; interpreter and everything below $50 is free while
; it does. Only the locations the code makes plain
; are named here; the rest of the map is not settled
; and is left as addresses rather than guessed at.
;   $00,$01  the return address, saved on entry
;   $04,$05  the hi-res address HPOSN builds
;   $06      the mask that selects the pixel in it
;   $34      the page base, $20 or $40
;   $BB,$BC  the turtle record, put there by HOOKUP
;            in the Pascal half
;---------------------------------------------------

RTN     .EQU 000        ; return address
SCRN    .EQU 004        ; hi-res address of the row
MASK    .EQU 006        ; bit within the byte
PAGE    .EQU 034        ; 020 for page 1, 040 for page 2
