{ SYSTEM.PASCAL -- the Apple Pascal operating system: command menu, file
  I/O primitives, error printing, initialization, and program loading.
  Codefile target is **128K.PASCAL** specifically (APPLE3:) -- the only
  build this project reads, cites, or tests against; the 64K
  `SYSTEM.PASCAL` build is out of scope entirely, by direct instruction
  (`analysis/diskset-inventory.txt` has 128K.PASCAL's own 7-segment
  layout).

  First session: the skeleton only. `PROGRAM PASCALSYSTEM` matches
  UCSD II.0's own program name exactly (`reference_source/ucsd_ii0/
  GLOBALS.TEXT`) and the shape SETUP.text's own header comment already
  worked out for a `(*$U-*)` host program wrapping `SEGMENT PROCEDURE`s
  one level in. `CONST`/`TYPE` and the VAR section below are ported
  from `GLOBALS.TEXT` (legitimate for names per the project's own
  sources-of-truth order -- UCSD source for names, re-derive structure
  from the binary) as a *starting point*, not yet verified against
  Apple's own frame sizes; `PASCALSY` (segment 0, the real 451-word
  main loop, `analysis/lifted/128K.PASCAL-1.3-128K.pas.txt`) is left a
  trivial outer body for now, deliberately deferred -- it is the single
  biggest procedure in the entire disk set and depends on getting these
  globals right first.

  **Write to the console with plain `WRITE`/`WRITELN` and no file
  argument** -- finding 201, and the correction of a claim this header
  carried for several sessions. What is true is narrower than it was
  written: Apple's compiler rejects a *dereference* as the `WRITE`
  sugar's explicit file argument (`WRITELN(SYSTERM^)`, error 125,
  where the host tool accepts it), and it rejects a string literal
  bound to a `VAR STRING` parameter (error 154, re-confirmed in
  isolation this session). Both are real. Neither one rules out the
  sugar, because the shape Apple actually used takes **no file
  argument at all**: `WRITE('literal')` lowers to `LOD 1,3` / `LSA` /
  `SLDC 0` / `CXP 0,19`, which is exactly what `128K.PASCAL` contains
  -- `LOD 1,3` is the compiler's own reference to the default output
  file, not an identifier anyone wrote. Because the compiler builds
  that call itself, the literal never faces the `VAR`-actual check
  that the same literal fails in a hand-written `FWRITESTRING(...)`
  call. VERIFIED SOURCE + BINARY FACT, from an already-closed pair:
  `FORMATTER.text`, a byte-identical reconstruction, writes
  `WRITELN('Apple Pascal Disk Formatter Program [1.3]')` and the
  shipped `FORMATTER.CODE` holds precisely that sequence.

  An *explicit* file argument still needs a direct
  `FWRITELN`/`FWRITESTRING` call, and `USERPROGRAM` below is the one
  place in this file that needs one, exactly as UCSD's own
  `SYSSEGS.A.TEXT` writes it (`FWRITELN(SYSTERM^)`). That is also
  why `FIB`, not `TEXT`, is `FWRITELN`'s own real parameter type
  (`GLOBALS.TEXT`'s own forward declaration, `PROCEDURE
  FWRITELN(VAR F: FIB); FORWARD;`) -- confirmed against the raw p-code
  too: `USERPROG.1` pushes `LOD 1,56` (a plain value load, not a
  dereference-then-load) straight into `CXP 0,22` (`OS.22`, i.e.
  segment-0 procedure 22 -- `FWRITELN`), meaning the real global at
  that offset is itself the pointer, loaded and passed as-is.

  That single fact reshaped this file: `GLOBALS.TEXT`'s own "SYSTEM
  PROCEDURE FORWARD DECLARATIONS" section (27 "fixed", addressed
  directly by object code, then 14 "non-fixed") is not a documentation
  aid, it is 41 of segment 0's own procedure declarations, and segment
  0's own body (`PASCALSY.1`, deferred) makes 42 -- exactly finding
  51a's own already-verified count for how far Apple's segment-0
  numbering agrees with UCSD's declared order. Declaring all 41 here,
  in this same order, before any `SEGMENT PROCEDURE`, lands their
  procedure *numbers* right even though every body but the two below
  is still a stub: `FINIT` (2nd declared) already matches an
  independently-recovered comment from earlier compiler work, `OS.3
  FINIT` -- procedure 3, one more than its declaration position because
  the enclosing block's own body always claims number 1.

  `USERPROGRAM` (segment 1, `USERPROG` on disk) is the one real body
  this session: UCSD's own `SYSSEGS.A.TEXT` gives it verbatim (once
  written as direct `FWRITELN`/`FWRITESTRING` calls, per above), and
  Apple's binary (`args 2 words`) matches UCSD's own 2-parameter
  declaration exactly -- unlike segment 0's own procedures 43 onward
  (finding 51c), this one is a straight, unmodified port. The other
  five segments are stubs: `PRINTERROR(XEQERR,IORSLT: INTEGER)`,
  `INITIALIZE`, and `GETCMD(LASTST: CMDSTATE): CMDSTATE` all match
  Apple's own real `args` word counts exactly against UCSD's declared
  signatures (`params=2/1/1` respectively, `analysis/lifted/
  128K.PASCAL-1.3-128K.pas.txt`), so those signatures are trusted;
  `FIOPRIMS` (`args 0 words`, real) and `FILEPROC` (`args 6 words`,
  real) have no UCSD precedent at all -- Apple-specific segments, most
  likely 128K-only code the 64K system keeps inline in segment 0.
  `FILEPROC`'s own six words dispatch on the first (`OP`) to one of
  several internal arms, mapped directly from the real binary's own
  `FILEPROC` segment (finding 156) -- `VAR F: FIB`, `VAR ARGSTR:
  STRING`, `ARGBOOL: BOOLEAN`, `ARGPTR: FIBP`, `ARGINT: INTEGER`. }

                          and 1.3)" -- 1.3 real, not UCSD generic }

                          this build targets 128K.PASCAL }

    { Eleven members, not UCSD's ten (finding 204). `GETNEXTCMD`'s own
      real body dispatches with `XJP 2..10` -- a nine-arm jump table
      whose highest label is ordinal **10** -- and tests membership with
      the set constant `2044`, which is bits 2 through 10. Ten members
      would stop at ordinal 9 and neither would be legal. Every other
      ordinal this file already relies on still checks out against the
      binary's own set constants: `224` is bits 5-7 (`COMPONLY`
      through `COMPDEBUG`) and `12` is bits 2-3 (`UPROGNOU`,
      `UPROGUOK`), so the extra member is appended at the end rather
      than inserted. Its NAME is not recoverable -- names never are --
      so it carries a placeholder. UCSD's own `GETCMD` has
      `CONST ASSEMONLY = LINKANDGO;`, and 1.3 is the release that put
      the assembler on the command line, which makes a real assemble
      state the obvious guess; a guess is not a name, so it stays
      `CMDST10` until something says otherwise. }

    FILL_STR = STRING[FILL_LEN];

                INFOFILE, DATAFILE, GRAFFILE, FOTOFILE, SECUREDIR);

    DIRENTRY = PACKED RECORD
                 DFIRSTBLK: INTEGER;  { first physical disk addr }
                 DLASTBLK: INTEGER;   { points at block following }
                 CASE DFKIND: FILEKIND OF
                   SECUREDIR,
                   UNTYPEDFILE:       { only in DIR[0] -- volume info }
                     (FILLER1: 0..2048;
                      DVID: VID;
                      DEOVBLK: INTEGER;
                      DNUMFILES: DIRRANGE;
                      DLOADTIME: INTEGER;
                      DLASTBOOT: DATEREC);
                   XDSKFILE, CODEFILE, TEXTFILE, INFOFILE,
                   DATAFILE, GRAFFILE, FOTOFILE:

                       `STATUS: BOOLEAN` wildcard flag: `FPCLOSE`'s
                       own `FHEADER.FILLER2 := 0` is `SLDC 12 |
                       SLDC 4 | SLDC 0 | STP` -- twelve bits at
                       right bit 4, one field, filling word 2 above
                       `DFKIND`. Exactly `FILLER1`'s shape in the
                       other variant. The Filer's wildcard bit lives
                       in here but the OS never names it. }
                     (FILLER2: 0..2048;
                      DTID: TID;
                      DLASTBYTE: 1..FBLKSIZE;
                      DACCESS: DATEREC)
               END;

    DIRP = ^DIRECTORY;
    DIRECTORY = ARRAY [DIRRANGE] OF DIRENTRY;

    { file information }
    CLOSETYPE = (CNORMAL, CLOCK, CPURGE, CCRUNCH);
    WINDOWP = ^WINDOW;
    WINDOW = PACKED ARRAY [0..0] OF CHAR;

    { The EXEC buffer is a type of its own and not a `WINDOW`, because
      `GETCMD.24`'s `NEW` says so: `LDA 2,381 | LDCI 256 | CSP 1`
      allocates **256 words**, and `NEW`'s size comes from the
      pointed-to type with nothing else to set it (finding 225). A
      `WINDOW` is one word -- widening `WINDOW` itself would change
      `INITIALIZE`'s own three `NEW(LWINDOW)` calls, which are exact.
      Nothing needs the two to be assignment-compatible: every use of
      `EXBUFPTR^` is either an index or an argument to a built-in
      (`BLOCKREAD`, `BLOCKWRITE`, `FILLCHAR`, `SCAN`), and a built-in
      takes any variable. }
    EXBUFP = ^EXBUF;
    EXBUF = PACKED ARRAY [0..511] OF CHAR;


    FIBP = ^FIB;

    FIB = RECORD
            FWINDOW: WINDOWP;  { user window, F^, used by GET/PUT }
            FEOF, FEOLN: BOOLEAN;
            FSTATE: (FJANDW, FNEEDCHAR, FGOTCHAR);
            FRECSIZE: INTEGER; { bytes; 0=>block file, 1=>char file }
            CASE FISOPEN: BOOLEAN OF
              TRUE: (FISBLKD: BOOLEAN;   { file is on a block device }
                     FUNIT: UNITNUM;
                     FVID: VID;
                     FREPTCNT,          { # times F^ valid w/o GET }
                     FNXTBLK,           { next rel block to IO }
                     FMAXBLK: INTEGER;  { max rel block accessed }
                     FMODIFIED: BOOLEAN;
                     FHEADER: DIRENTRY; { copy of disk dir entry }
                     CASE FSOFTBUF: BOOLEAN OF
                       TRUE: (FNXTBYTE, FMAXBYTE: INTEGER;
                              FBUFCHNGD: BOOLEAN;
                              FBUFFER: PACKED ARRAY [0..FBLKSIZE] OF CHAR))
          END;

    INFOREC = RECORD
                SYMFIBP, CODEFIBP: FIBP;         { workfiles for scratch }

    SEG_DESC = RECORD

               END;

    { debugger stuff }
    BYTERANGE = 0..255;
    TRICKARRAY = RECORD              { memory diddling for EXECERROR }
                   CASE BOOLEAN OF
                     TRUE: (WORD: ARRAY [0..0] OF INTEGER);
                     FALSE: (BYTE: PACKED ARRAY [0..0] OF BYTERANGE)
                 END;
    MSCWP = ^MSCW;                   { mark stack record pointer }
    MSCW = RECORD
             STATLINK: MSCWP;        { pointer to parent MSCW }
             DYNLINK: MSCWP;         { pointer to caller's MSCW }
             MSSEG, MSJTAB: ^TRICKARRAY;
             MSIPC: INTEGER;
             LOCALDATA: TRICKARRAY
           END;

    SEG_ENTRY = RECORD
                  CODEUNIT: UNITNUM;
                  CODEDESC: SEG_DESC
                END;
    SYSCOMREC = RECORD

                  XEQERR: INTEGER;    { reason for EXECERROR call }

                  GDIRP: DIRP;        { global dir pointer, see VOLSEARCH }
                  LASTMP, STKBASE, BOMBP: MSCWP;
                  MEMTOP, SEG, JTAB: INTEGER;
                  BOMBIPC: INTEGER;   { where EXECERROR blowup was }
                  HLTLINE: INTEGER;   { more debugger stuff }
                  BRKPTS: ARRAY [0..3] OF INTEGER;
                  RETRIES: INTEGER;   { drivers put retry counts }
                  EXPANSION: ARRAY [0..8] OF INTEGER;
                  HIGHTIME, LOWTIME: INTEGER;
                  MISCINFO: PACKED RECORD
                              NOBREAK, STUPID, SLOWTERM,
                              HASXYCRT, HASLCCRT, HAS8510A, HASCLOCK: BOOLEAN;
                              USERKIND: (NORMAL, AQUIZ, BOOKER, PQUIZ);
                              WORD_MACH, IS_FLIPT: BOOLEAN
                            END;
                  CRTTYPE: INTEGER;
                  CRTCTRL: PACKED RECORD
                             RLF, NDFS, ERASEEOL, ERASEEOS, HOME,
                             ESCAPE: CHAR;
                             BACKSPACE: CHAR;
                             FILLCOUNT: 0..255;
                             CLEARSCREEN, CLEARLINE: CHAR;
                             PREFIXED: PACKED ARRAY [0..15] OF BOOLEAN
                           END;
                  CRTINFO: PACKED RECORD
                             WIDTH, HEIGHT: INTEGER;
                             RIGHT, LEFT, DOWN, UP: CHAR;
                             BADCH, CHARDEL, STOP, BREAK, FLUSH, EOF: CHAR;
                             ALTMODE, LINEDEL: CHAR;
                             ALPHA_LOCK, ETX, PREFIX: CHAR;
                             PREFIXED: PACKED ARRAY [0..15] OF BOOLEAN
                           END;
                  SEGTABLE: ARRAY [SEG_RANGE] OF SEG_ENTRY
                END;

    PL: STRING;                      { prompt-line string, see PROMPT }
    IPOT: ARRAY [0..4] OF INTEGER;   { integer powers of ten }

      block number through `ORD`, and that is not a guess: the binary
      uses the raw word three ways that cannot all be one type under
      ordinary Pascal. `LOD 1,385 | LAND` and `LOD 1,385 | FJP` are a
      BOOLEAN operand and a BOOLEAN condition with no `SLDC 0 | NEQI`
      anywhere, and declaring it `INTEGER` and writing `AND EXEC_BLK`
      is **error 134** on Apple's own compiler (tried, this session);
      but `LOD 1,385 | SLDC 1 | ADI | STR 1,385` is arithmetic, and the
      same word is `FBLOCKIO`'s own `RBLOCK` argument. `SUCC` and `ORD`
      are the two operations that cross that line for free -- neither
      emits an instruction -- so `EXEC_BLK := SUCC(EXEC_BLK)` and

    { `FIOPRIMS.2` -- soft-buffer window advance (finding 174, closing
      finding 170's own standing gap). Copies up to `FRECSIZE` bytes
      from the in-memory soft buffer into the user's window (`F^`),
      pulling in fresh disk blocks via `UNITREAD` as needed and flushing
      a dirty buffer via `UNITWRITE` first when one is pending. `ROOM`
      is computed one of two ways depending on whether `FNXTBLK` is
      still short of `FMAXBLK` (already-known blocks ahead -- use the
      full `512`) or at/past it (the file's last known block -- use
      `FHEADER.DLASTBYTE`, the true end of valid data, and give up with
      no advance at all if even one more record would run past
      `FNXTBYTE`, the real `EOF` case). `NEED` clamps `RECSIZE` to
      `ROOM`; a `MOVELEFT` copies what's available this pass and updates
      `FNXTBYTE`/`WINOFS`/`RECSIZE`; if `RECSIZE` isn't yet `0`, the loop
      writes back a dirty block, reads the next one, and retries.
      Result is `TRUE` only on the genuine-`EOF`/`IORESULT`-error exits
      (via `GOTO`, matching the real binary's own jump table entry for
      an early return past the trailing `FPWINADV := FALSE`); `FALSE`
      once the loop's own natural exit is reached, `RECSIZE = 0`.

      Two systematic gaps, not forced: the real binary caches `F`'s own
      address into a *second* local (`STL 9`) even though it's already
      a trivially-addressable `VAR` parameter, on top of the expected
      `FHEADER` cache -- the same `WITH F DO WITH FHEADER DO` idiom used
      successfully elsewhere in this file (`CANTSTRETCH`, finding 165) still
      doesn't reproduce that extra, semantically-redundant caching
      step under this host compiler; `params=6` bytes exact, `locals=12`
      against the real `14`, two words short from this alone.

      Separately: `DIRENTRY.DLASTBYTE` is declared `1..FBLKSIZE`
      (`1..512`, needing all 10 bits) and this host compiler always
      compiles any access to it as a packed load/store (`LDP`/`STP`,
      confirmed by an isolated probe compiling `D.DLASTBYTE := 5` in
      total isolation) -- but the real binary's own `FHEADER.DLASTBYTE`
      read here is a plain unpacked `IND`/`STO`, no `LDP` anywhere
      nearby. `DLASTBYTE` doesn't share a word with any neighboring
      field in this variant (`FILLER2` and `DACCESS` are packed
      separately), so Apple's own compiler evidently doesn't bother
      packing a subrange into fewer than its natural word when doing so
      saves nothing -- a real compiler-behavior divergence from this
      host tool, not a source-level choice available to fix. Any other
      already-written `DLASTBYTE` reference in this file (`CANTSTRETCH`,
      `FPCLOSE`) carries the same latent, previously-undetected gap.

      **Exact** since finding 215, and the one thing left was a shape,
      not an offset: the `FNXTBLK >= FMAXBLK` test's `THEN` part is
      `IF ... THEN GOTO 1 ELSE ROOM := ...`, an `IF`/`ELSE` where this
      had a `BEGIN ... ; ... END`. Both are correct Pascal and mean the
      same thing; only the `ELSE` emits the second `UJP` Apple has.
      Two consecutive `UJP`s are the signature -- look for a missing
      `ELSE`, not for a missing statement. }
    FUNCTION FPWINADV;
      LABEL 1;
      VAR
        RECSIZE, WINOFS, ROOM, NEED: INTEGER;
        FILLED: BOOLEAN;
    BEGIN
      FPWINADV := TRUE;
      WITH F DO
        WITH FHEADER DO
        BEGIN
          RECSIZE := FRECSIZE;
          WINOFS := 0;
          REPEAT
            IF FNXTBLK >= FMAXBLK THEN
              IF (FNXTBYTE + RECSIZE) > FMAXBYTE THEN
                GOTO 1
              ELSE
                ROOM := DLASTBYTE - FNXTBYTE
            ELSE
              ROOM := 512 - FNXTBYTE;
            NEED := RECSIZE;
            IF NEED > ROOM THEN NEED := ROOM;
            IF NEED > 0 THEN
            BEGIN
              MOVELEFT(FBUFFER[FNXTBYTE], FWINDOW^[WINOFS], NEED);
              FNXTBYTE := FNXTBYTE + NEED;
              WINOFS := WINOFS + NEED;
              RECSIZE := RECSIZE - NEED
            END;
            FILLED := RECSIZE = 0;
            IF NOT FILLED THEN
            BEGIN
              IF FBUFCHNGD THEN
              BEGIN
                FBUFCHNGD := FALSE;
                FMODIFIED := TRUE;
                UNITWRITE(FUNIT, FBUFFER[0], 512, DFIRSTBLK + FNXTBLK - 1)
              END;
              IF IORESULT <> 0 THEN GOTO 1;
              UNITREAD(FUNIT, FBUFFER[0], 512, DFIRSTBLK + FNXTBLK);
              IF IORESULT <> 0 THEN GOTO 1;
              FNXTBLK := FNXTBLK + 1;
              FNXTBYTE := 0
            END
          UNTIL FILLED;
          FPWINADV := FALSE
        END;
      1: ;
    END;

    { `FIOPRIMS.3` -- DLE-blank expansion (finding 171). Called by
      `FGET` only right after reading a literal `DLE` (`16`) byte, per
      `FGET`'s own gate. Reads the *next* byte (the two-byte DLE code's
      count, `+32`, this file's own already-quoted manual comment on
      `DLE`-blank codes). A real count byte is always at least `32`
      and in practice `> ' '`, so that is the *decode* arm, not the
      rejection: it loads `FREPTCNT` with the decoded blank count and
      replaces the window byte with a space. Only a byte at or below
      `' '` is a spurious `DLE` -- read past it and report `FALSE`, no
      compression applied. An earlier reading had the two arms the
      wrong way round; the binary puts the decode where the `FJP`
      falls through -- `FGET`'s own opening guard (`IF F.FREPTCNT >
      0 THEN` decrement and return early, no real read) is exactly what
      consumes this: each of the next `FREPTCNT` `GET`s just replays
      the cached space with no further I/O. `params=6` bytes exact;
      the one `data` word is the `WITH F DO` (finding 217). }
    FUNCTION FPDLE;
    BEGIN
      FGET(F);
      WITH F DO
        IF FWINDOW^[0] > ' ' THEN
        BEGIN
          FREPTCNT := ORD(FWINDOW^[0]) - 32;
          FWINDOW^[0] := ' ';
          FPDLE := TRUE
        END
        ELSE
        BEGIN
          FGET(F);
          FPDLE := FALSE
        END
    END;

    { `FIOPRIMS.4` -- speculative lookahead `GET` with rollback

      from the locals count alone), advances `FNXTBLK` and sets

      for real. If that hits real `EOF`, rolls the whole `FIB` back

      `FEOF`/`FEOLN` true with `FNXTBYTE` backed off by one -- a

    { `FIOPRIMS.5` -- the *write* counterpart of `FPWINADV`, and its
      caller is now known: `FPUT` (`PASCALSY.8`) calls `CXP 2,5`, and
      this body calls `CXP 0,8` (`FPUT`) straight back, so the two are
      mutually recursive across the segment boundary. Decoded from the
      addressed disassembly; the frame is `FPWINADV`'s exactly
      (`params=6`, `data=14`, same five variables and the same two
      `WITH` pointers at 9 and 10), and the first twelve instructions
      are byte-for-byte `FPWINADV`'s, which is what pinned the local
      numbering before a line of it was written.

      It copies `FRECSIZE` bytes the other way -- out of the user's
      window (`F^`) into the soft buffer -- flushing and refilling as
      it crosses block boundaries. Three things differ from
      `FPWINADV` and each is in the binary:

        * The loop opens by *growing the file* when the write would
          run past the last allocated block: `(DFIRSTBLK + FNXTBLK) =
          DLASTBLK` and the record would overrun `DLASTBYTE` calls
          `CANTSTRETCH` (`CXP 0,49`, the extend-allocation routine), and
          only if that fails does it report `INOROOM` and give up.
          The `FJP` to the loop top is `jtab-10` at `$0186`, which is
          instruction 12 -- the same offset as `FPWINADV`'s -- so this
          test is *inside* the `REPEAT`, retried on every pass, not a
          one-time check ahead of it.
        * `FBUFCHNGD := TRUE` before the `MOVELEFT`, since this is the
          side that dirties the buffer.
        * Past the loop it maintains the high-water mark
          (`FMAXBLK`/`FMAXBYTE`) and then, for a single-byte
          `TEXTFILE` window holding a carriage return near the end of
          the first block, backs `FNXTBYTE` up to `512 - 1`, blanks
          the window byte and recurses into `FPUT` -- the line-crossing
          case that keeps a `TEXTFILE` line from straddling the
          two-block page the editor reads.

      `NOT ODD(FNXTBLK)` is not a paraphrase: `ODD` and `CHR` are the
      two standard functions the compiler generates *no instruction*
      for (`BODYPART.text`'s own `IF (CSPNUM <> 21) AND (CSPNUM <> 22)
      THEN GEN1(30(*CSP*),CSPNUM)`), so `ODD(<integer>)` is a free
      cast to `BOOLEAN` and `IND 13 | LNOT` is exactly what it emits.
      See finding 231 -- that one line reopened all four procedures
      finding 230 had written off as unreachable. }
    FUNCTION FPWINOUT;
      LABEL 1;
      VAR
        RECSIZE, WINOFS, ROOM, NEED: INTEGER;
        FILLED: BOOLEAN;
    BEGIN
      FPWINOUT := TRUE;
      WITH F DO
        WITH FHEADER DO
        BEGIN
          RECSIZE := FRECSIZE;
          WINOFS := 0;
          REPEAT
            IF ((DFIRSTBLK + FNXTBLK) = DLASTBLK) AND
               ((FNXTBYTE + RECSIZE) > DLASTBYTE) THEN
              IF CANTSTRETCH(F) THEN
              BEGIN
                SYSCOM^.IORSLT := INOROOM;
                GOTO 1
              END;
            IF (DFIRSTBLK + FNXTBLK) = DLASTBLK THEN
              IF (FNXTBYTE + RECSIZE) > DLASTBYTE THEN
              BEGIN
                SYSCOM^.IORSLT := INOROOM;
                GOTO 1
              END
              ELSE
                ROOM := DLASTBYTE - FNXTBYTE
            ELSE
              ROOM := 512 - FNXTBYTE;
            NEED := RECSIZE;
            IF NEED > ROOM THEN NEED := ROOM;
            IF NEED > 0 THEN
            BEGIN
              FBUFCHNGD := TRUE;
              MOVELEFT(FWINDOW^[WINOFS], FBUFFER[FNXTBYTE], NEED);
              FNXTBYTE := FNXTBYTE + NEED;
              WINOFS := WINOFS + NEED;
              RECSIZE := RECSIZE - NEED
            END;
            FILLED := RECSIZE = 0;
            IF NOT FILLED THEN
            BEGIN
              IF FBUFCHNGD THEN
              BEGIN
                FBUFCHNGD := FALSE;
                FMODIFIED := TRUE;
                UNITWRITE(FUNIT, FBUFFER[0], 512, DFIRSTBLK + FNXTBLK - 1)
              END;
              IF IORESULT <> 0 THEN GOTO 1;
              IF FNXTBLK < FMAXBLK THEN
                UNITREAD(FUNIT, FBUFFER[0], 512, DFIRSTBLK + FNXTBLK)
              ELSE
                FILLCHAR(FBUFFER[0], 512, CHR(0));
              IF IORESULT <> 0 THEN GOTO 1;
              FNXTBLK := FNXTBLK + 1;
              FNXTBYTE := 0
            END
          UNTIL FILLED;
          IF FNXTBLK > FMAXBLK THEN
          BEGIN
            FMAXBYTE := FNXTBYTE;
            FMAXBLK := FNXTBLK
          END
          ELSE
            IF (FNXTBLK = FMAXBLK) AND (FNXTBYTE > FMAXBYTE) THEN
              FMAXBYTE := FNXTBYTE;
          IF FRECSIZE = 1 THEN
            IF FWINDOW^[0] = CHR(13) THEN
              IF DFKIND = TEXTFILE THEN
                IF (FNXTBYTE >= 512 - 127) AND NOT ODD(FNXTBLK) THEN
                BEGIN
                  FNXTBYTE := 512 - 1;
                  FWINDOW^[0] := CHR(0);
                  FPUT(F)
                END;
          FPWINOUT := FALSE
        END;
      1: ;
    END;

  BEGIN
  END;

      VAR
        I: INTEGER;
    BEGIN

      { `.13` -- merge one library's dictionary into `WHAT_L`. A
        segment survives only if it is an intrinsic or a data segment,
        nobody has already supplied it, and the host actually asked for
        it; everything else has its `CODELENG` zeroed so `BINDSEGS` will
        not enter it in `SEGTABLE`. The three tests are `LAND`ed, not
        an `FJP` chain, so they are one `AND` expression. }
      PROCEDURE MERGELIB;
        VAR
          SNO: INTEGER;
          I: INTEGER;
      BEGIN
        FOR I := 0 TO 15 DO
        BEGIN
          SNO := SEGOFENT(BLK.D, I);
          IF (BLK.D.SEGKIND[I] IN [LINKED_INTRINS, DATASEG]) AND
             NOT (SNO IN WHAT_L) AND (SNO IN ST.INTRINSSEGS) THEN
          BEGIN
            WHAT_L := WHAT_L + [SNO];
            USEDIT := TRUE
          END
          ELSE
            BLK.D.DISKINFO[I].CODELENG := 0
        END;
        BINDSEGS(BLK.D, F)
      END;

      PROCEDURE OPENLIB(LTITLE: STRING);
      BEGIN
        FINIT(F, NIL, -1);
        FOPEN(F, LTITLE, TRUE, NIL);
        USEDIT := FALSE;
        IF IORESULT = 0 THEN
        BEGIN
          GOTLIB := TRUE;

            WRITE(LTITLE);
            WRITE(' is not used');

      { `.15` -- split the `LIBRARY FILES:` text block into up to five
        titles. `IX` starts at 15, one past the heading and its own
        carriage return; `CHR(16)` is a text file's own DLE blank
        compression, whose count byte has to be stepped over as well;
        `$` ends the list. `data=8` is four words -- three variables
        and the `FOR` limit -- so the two `EXIT(SPLITLIB)` paths are the
        real control flow, not a flag. }
      PROCEDURE SPLITLIB;
        VAR
          NAMELEN: INTEGER;
          IX: INTEGER;
          LIBX: INTEGER;
      BEGIN
        IX := 15;
        IF BLK.C[IX] = CHR(16) THEN
          IX := IX + 2;
        NAMELEN := 0;
        IF NOT ((BLK.C[IX] = '$') AND (BLK.C[IX + 1] = '$')) THEN
        BEGIN
          FOR LIBX := 1 TO 5 DO
          BEGIN
            NAMELEN := SCAN(80, =CHR(13), BLK.C[IX]);
            MOVELEFT(BLK.C[IX], LIBLIST[LIBX][1], NAMELEN);
            LIBLIST[LIBX][0] := CHR(NAMELEN);
            IX := IX + NAMELEN + 1;
            IF BLK.C[IX] = CHR(16) THEN
              IX := IX + 2;
            IF BLK.C[IX] = '$' THEN
            BEGIN
              NLIBS := LIBX;
              EXIT(SPLITLIB)
            END
          END;
          NLIBS := 5
        END
        ELSE
          NLIBS := 0
      END;

        either a codefile or a text file listing other libraries, and
        the second text block decides: `MOVELEFT` fourteen characters

        `LIBRARY FILES:` hand the block to `.15` and leave. Otherwise

        PROCEDURE TOUPPER;
          VAR I: INTEGER;
        BEGIN
          FOR I := 1 TO 13 DO
            IF S[I] >= 'a' THEN
              S[I] := CHR(ORD(S[I]) - 32)

      BEGIN

    { `GETCMD.19` = `ASSOCIATE`, UCSD's own routine carried into 1.3
      and extended: open a codefile by title, read block 0, check what
      it finds there, and bind its segments into `SYSCOM^.SEGTABLE`.
      259 instructions, `params`/`data` `16`/`728`, the largest
      procedure decoded for this file so far.

      The parameter list is UCSD's five plus one, and the sixth is a
      BOOLEAN, not the INTEGER this file guessed: the body reads it
      with `SLDL 3` twice, once as a plain condition and once under
      `LNOT`. It gates the version check, so it is named `CHECKVER`
      here for what it does; the real name is not recoverable.
      Reversal puts it on word `3` and `TITLE` on word `8`, and the
      three BOOLEANs land `7`/`6`/`5` in declaration order -- which is
      how `ERROROK` was identified, since word `5` is what guards the
      two error messages (finding 175, and finding 205 for the rest).

      Three things here have no UCSD precedent at all:

      * `RUN_VOL` (global word `444`) is **saved on entry, set to the
        volume `SCANTITLE` parses out of the title, and restored at
        label 1** -- so a failed associate leaves it alone and a
        successful one does not, because the success path does its own
        `FCLOSE` and then `EXIT(ASSOCIATE)` straight past the restore.
        That is deliberate, not a leak: it is what makes 1.3's own
        `%` volume prefix mean "wherever the code file came from",
        and `SCANTITLE`'s own `'%'` arm reads the very same word --
        which is how the two were finally connected (finding 205b).
        This file had declared `RUN_VOL` all along, at the right
        offset, with Tribby's own "run (%) volume" comment beside it,
        and still wrote `DKVID` in both places that use it.
      * The version check. `SEGINFO[1].VERSION <> 6` is the SEGINFO
        version field -- 1.1 writes `2`, 1.3 writes `6` -- and the
        `SYSTEM.COMPILER`/`FORTRAN:` escape beside it is Apple letting
        the Apple FORTRAN compiler, which ships as a `SYSTEM.COMPILER`
        whose segment 1 is named `FORTRAN:`, past a check aimed at
        1.1 binaries.
      * Intrinsic units. `INTRINSSEGS`, the four-word set at `0x120`
        of the dictionary, is intersected with the set `.10` builds
        out of the file's own segments; a non-empty intersection is
        "Conflict between intrinsic and user segment(s)", and a
        non-empty `INTRINSSEGS` alone sends the file through `.11`
        (`data` `1796` -- it reads `SYSTEM.LIBRARY`'s own dictionary).
        None of this exists in UCSD II.0.

      The `WITH` is three deep and its first element is never read:
      `LOD 2,1 | STL 370` opens `SYSCOM^` and nothing in the body
      touches it. UCSD's own `WITH USERINFO,SYSCOM^ DO` needed it for
      `SYSCOM^.IORSLT`; 1.3 calls `IORESULT` instead and the `WITH`
      stayed behind. }
    FUNCTION ASSOCIATE;
      LABEL 1;
      VAR
        SEGTBL: SEGDICT;
        LSEGS: SEGSET;
        TTITLE: STRING;
        SAVEVID: VID;
        TVID: VID;
        TTID: TID;
        TSEGS: INTEGER;
        TKIND: FILEKIND;
        OK: BOOLEAN;
    BEGIN
      ASS_STATUS := NOT_FOUND;
      ASSOCIATE := FALSE;
      SAVEVID := RUN_VOL;
      TTITLE := TITLE;
      OK := SCANTITLE(TTITLE, TVID, TTID, TSEGS, TKIND);
      RUN_VOL := TVID;
      IF NOT OK THEN
        RUN_VOL := '';
      FOPEN(USERINFO.CODEFIBP^, TITLE, TRUE, NIL);
      IF IORESULT <> 0 THEN
      BEGIN
        IF ERROROK THEN
          IF IORESULT = 7 THEN
            WRITE('Illegal file name')
          ELSE
            WRITE('No file ', TITLE);
        GOTO 1
      END;
      ASS_STATUS := FOUND_BAD;
      WITH SYSCOM^, USERINFO.CODEFIBP^, FHEADER DO
        IF DFKIND <> CODEFILE THEN
        BEGIN
          WRITE(TITLE, ' not code');
          GOTO 1
        END
        ELSE
        BEGIN
          UNITREAD(FUNIT, SEGTBL, SIZEOF(SEGTBL), DFIRSTBLK);
          IF IORESULT <> 0 THEN
          BEGIN
            WRITE('Bad block #0');
            GOTO 1
          END;
          IF CHECKVER THEN
            IF SEGTBL.SEGINFO[1].VERSION <> 6 THEN
              IF NOT ((POS('SYSTEM.COMPILER', TITLE) <> 0) AND
                      (SEGTBL.SEGNAME[1] = 'FORTRAN:')) THEN
              BEGIN
                WRITELN;
                WRITE(TITLE, ' is not version 1.3');
                GOTO 1
              END;
          IF NOT CHECKVER THEN
            FIXINTR(SEGTBL);
          IF NOT FILLSEGS(SEGTBL, LSEGS, [LINKED]) THEN
          BEGIN
            IF OKTOLINK THEN
            BEGIN
              WRITE('Linking...');
              WRITELN;
              FCLOSE(USERINFO.CODEFIBP^, CNORMAL);
              IF SYSASSOC(LINKER, TRUE) THEN
              BEGIN
                IF RUNONLY THEN
                  GETCMD := LINKANDGO
                ELSE
                  GETCMD := LINKDEBUG;
                EXIT(GETCMD)
              END
            END
            ELSE
              IF NOT (LASTST IN [LINKANDGO, LINKDEBUG]) THEN
                WRITE('Must L(ink first');
            GOTO 1
          END;
          IF (LSEGS * SEGTBL.INTRINSSEGS) <> [] THEN
          BEGIN
            WRITE('Conflict between intrinsic and user segment(s)');
            GOTO 1
          END;
          IF SEGTBL.INTRINSSEGS <> [] THEN
            IF NOT USELIB(TITLE, SEGTBL) THEN
              GOTO 1;

      FCLOSE(USERINFO.CODEFIBP^, CNORMAL);

    { `GETCMD.3` = `SYSASSOC` (finding 226): bind one of the five
      system files, and if its recorded pathname no longer finds it,
      hunt for the same *file name* on every mounted block device and
      rewrite `FILENAME` with wherever it turned up.

      `data=41` accounts word for word, and the last twelve are the
      compiler's own: `CONCAT` builds into a hidden `FULL_ID`
      temporary, one `SCONCAT` per argument with a running cumulative
      maximum for the third argument (`7`, `8`, `23` -- not each
      piece's own length), then assigns it out. `LLA 34` is that
      temporary and `LLA 20` is `TRYTITLE`; the `WITH UNITABLE[UNITNO]`
      pointer at 33 sits between them, after every declaration and
      before the temporary, which is what allocation order predicts.

      The trailing `ASSOCIATE` is called for its side effect only --
      it reports the error -- and the result is discarded with the
      same `IF <call> THEN` shape `FBLOCKIO` uses for `CANTSTRETCH`. }

    { `GETCMD.20` = `STARTCOMPILE`, the largest single body in the file
      at 342 instructions, and `GETCMD.21` nested inside it. The names
      are this project's own.

      It binds the assembler or the compiler, settles what to read and
      what to write, opens all three files, and returns a `CMDSTATE`
      that sends the caller off to run the tool. `NEXTST` has to be a
      `CMDSTATE` and not an `INTEGER`, because the last thing the body
      does is `SLDL 1 | SRO 1` -- assign the parameter straight to
      `GETCMD`'s own result.

      Its ordinal is doing double duty, which is worth writing down
      because it looks like a bug and is not: `'A'` passes
      `LINKANDGO`, `'C'` passes `COMPONLY` and `RUNWORKFILE` passes
      `COMPANDGO`. The `8` is only ever a marker for "assemble" -- it
      chooses `ASSMBLER` over `COMPILER` and the word `Assembling`
      over `Compiling` -- and is normalised back to `COMPONLY` in the
      three instructions before the result is stored, so no caller
      ever sees `LINKANDGO` come back out of here.

      `GETCMD.21` has `params=0 data=0` and exists only to strip
      leading blanks from its parent's `SRCTITLE`; both the string it
      edits and the `IX` it leaves behind are the parent's words
      (`LDA 1,2`, `STR 1,56`).

      The single `LABEL 1` is real. Six different failure paths jump
      to the same pair of `FCLOSE`s at the end, and the `IF <cond>
      THEN GOTO 1 ELSE ...` shape shows up in the binary as a `UJP` to
      the label immediately followed by a second, unreachable `UJP`
      over the else part -- the compiler emits its skip-the-else jump
      whether or not the then part can fall out of.

      `data=396` is 198 words and comes out exact, but one part of it
      is reproduced rather than understood. The declarations account
      for `2`-`59` and the `CONCAT` temporary starts at `60` as
      allocation order predicts; the `COPY` temporary nested inside
      that same statement is at `188`, not at `80` where a
      `STRING[38]` temporary would leave it, so something in
      `CONCAT(COPY(...), 'SYSTEM.SWAPDISK')` claims 128 words -- half
      a `STRING[255]`. Apple's compiler does it from this source and
      so the bytes match, but no rule in this file predicts it yet. }
    PROCEDURE STARTCOMPILE(NEXTST: CMDSTATE);
      LABEL 1;
      VAR
        SRCTITLE: STRING[40];
        BASENAME: STRING[40];
        CODETITL: FULL_ID;
        IX: INTEGER;
        WHICH: SYSFILE;
        IOERR: INTEGER;
        OK: BOOLEAN;
      PROCEDURE TRIMLEAD;
      BEGIN
        IX := 1 + SCAN(LENGTH(SRCTITLE), <>' ', SRCTITLE[1]);
        DELETE(SRCTITLE, 1, IX - 1)
      END;
    BEGIN
      IF NEXTST = LINKANDGO THEN
        WRITE('Assembling')
      ELSE
        WRITE('Compiling');
      WRITE('...');
      WRITELN;
      IF NEXTST = LINKANDGO THEN
        WHICH := ASSMBLER
      ELSE
        WHICH := COMPILER;
      IF SYSASSOC(WHICH, TRUE) THEN
      BEGIN
        IF USERINFO.GOTSYM THEN
          SRCTITLE := CONCAT(USERINFO.SYMVID, ':', USERINFO.SYMTID)
        ELSE
        BEGIN
          IF NEXTST = LINKANDGO THEN
            WRITE('Assemble')
          ELSE
            WRITE('Compile');
          WRITE(' what textfile (<ret> to exit) ? ');
          READ(SRCTITLE);
          READLN;
          TRIMLEAD;
          IF SRCTITLE = '' THEN
            GOTO 1
          ELSE
            IF SRCTITLE[1] = CHR(27) THEN
              GOTO 1
            ELSE
            BEGIN
              IF BADTITLE(SRCTITLE) THEN
                EXIT(STARTCOMPILE);
              TITLENORM(SRCTITLE, TRUE, 40)
            END
        END;
        BASENAME := SRCTITLE;

        IF (IX <> 0) AND (IX = LENGTH(BASENAME) - 4) THEN
          DELETE(BASENAME, IX, 5);
        FOPEN(USERINFO.SYMFIBP^, SRCTITLE, TRUE, NIL);
        IF IORESULT <> 0 THEN
        BEGIN
          WRITE('Can''t find ');
          WRITE(SRCTITLE);
          USERINFO.GOTSYM := FALSE;
          GOTO 1
        END;
        SRCTITLE := CONCAT(COPY(FILENAME[WHICH], 1,
                                POS(':', FILENAME[WHICH])),
                           'SYSTEM.SWAPDISK');
        FOPEN(SWAPFIB^, SRCTITLE, TRUE, NIL);
        CODETITL := '*SYSTEM.WRK.CODE[*]';
        REPEAT
          OK := TRUE;

            READ(SRCTITLE);
            READLN;

                DELETE(SRCTITLE, 1, 2);

                GOTO 1
              ELSE
              BEGIN

                IF IX > 0 THEN
                BEGIN

                  INSERT(BASENAME, SRCTITLE, IX)
                END;

                  GOTO 1;
                TITLENORM(SRCTITLE, FALSE, 23);
                CODETITL := SRCTITLE
              END
          END;

          BEGIN

            WRITE(IOERR);
            WRITE(' occured while opening ');
            WRITE(CODETITL);

              GOTO 1
          END

        USERINFO.ERRNUM := 0;
        USERINFO.ERRBLK := 0;
        USERINFO.ERRSYM := 0;

          NEXTST := COMPONLY;
        GETCMD := NEXTST;
        EXIT(GETCMD);
      1:
        FCLOSE(USERINFO.SYMFIBP^, CNORMAL);
        FCLOSE(SWAPFIB^, CNORMAL)
      END
    END;

    { `GETCMD.22` (finding 226) -- what happens after a compile
      finishes. Close the symbol workfile and the swap file; on an
      error, purge the code workfile and, if the error carries a
      block number, go straight into the Editor by exiting the whole
      segment with `GETCMD := SYSPROG`. On success, promote the
      compiler's output title into `USERINFO`'s workfile fields,
      stripping a trailing `.CODE`, and run it if the command asked
      for that.

      compiler's own result temporaries for `COPY`, which is `SCOPY`
      into a hidden variable followed by an assignment out of it
      (`CXP 0,25` bracketed by the destination address and a `SAS`).
      `USERINFO`'s field offsets fall out of the same within-clause
      reversal as everywhere else -- `LOD 2,8` is `CODEFIBP` and
      `LOD 2,9` is `SYMFIBP` because they were declared
      `SYMFIBP, CODEFIBP`.

      `data=17` against sixteen words of temporary: both `COPY` temps
      sit one word higher than the compiler puts them unaided (`LLA 2`
      and `LLA 10` against `LLA 1` and `LLA 9`), with every instruction
      otherwise identical. Temporaries are allocated after declared
      variables, so one declared word stands ahead of them and nothing
      in the body touches it -- the third time this file has produced
      one, after `PROMPT` (finding 217) and `INITSYSCOM`'s word 282
      (finding 223c). }

    { `GETCMD.25` -- the `X(ecute` command, and the reader half of the
      EXEC-file pair `.27` writes. The name is this project's own, not
      recovered: there is no UCSD precedent for any of this.

      A title beginning `EXEC/` (upshifted first, four characters, not
      five -- the `/` needs none) is an exec file rather than a
      program: strip the prefix, `RESET` it, and prime the buffer,
      taking the file's own first character as `EXEC_TERM`. Anything
      else is associated and run.

      `FROMCHAIN` is a `BOOLEAN` because `SLDL 1 | FJP` uses the
      parameter word as a condition with no comparison; when it is set
      the title comes from `CHAIN_NAME` (word `328`) and nothing is
      prompted for.

      `data=174` is 87 words and it is what settles how a `COPY`
      temporary is sized. `S` is 41 words at 2, `PREFIX` 3 at 43, `I`
      at 46, `CH` at 47 -- 46 words of declarations -- and the
      remaining 41 are one temporary, which is `STRING[80]`: the size
      of `COPY`'s own *source*, not of the five characters copied and
      not of the `STRING[5]` assigned to. `GETCMD.18` and `GETCMD.22`
      both agree (their sources are `TID`s and their temporaries eight
      words), and it is the same slot the `FOR` limit reuses
      afterwards at `STL 48`.

      One name is left open. `SLDC 1 | SLDC 4 | LDP` off `SYSCOM^+29`
      is a one-bit field at bit 4 of `MISCINFO`, which under the
      field order this file already carries is `HASLCCRT` -- so that
      is what is written here, because the operands are what the
      compare tests and they are not in doubt. Why a lower-case
      display should suppress the long prompt is not obvious, and the
      alternative (that `MISCINFO`'s declared order is off by
      something) cannot be settled from this procedure alone. Recorded
      rather than guessed at. }
    PROCEDURE XECUTE;
      VAR
        S: STRING;
        PREFIX: STRING[5];
        I: INTEGER;
        CH: CHAR;
    BEGIN
      IF FROMCHAIN THEN
        S := CHAIN_NAME
      ELSE
      BEGIN
        WRITE('Execute');
        IF NOT SYSCOM^.MISCINFO.SLOWTERM THEN
          WRITE(' what file (<ret> to exit) ');
        WRITE('? ');
        READ(S);
        READLN
      END;
      IF LENGTH(S) > 0 THEN
      BEGIN
        IF LENGTH(S) > 5 THEN
        BEGIN
          PREFIX := COPY(S, 1, 5);
          FOR I := 1 TO 4 DO
          BEGIN
            CH := PREFIX[I];
            IF (CH >= 'a') AND (CH <= 'z') THEN
              PREFIX[I] := CHR(ORD(CH) - 32)
          END;
          IF PREFIX = 'EXEC/' THEN
          BEGIN
            IF W_EXEC_FLG THEN
              EXECOPNERR(1)
            ELSE
            BEGIN
              DELETE(S, 1, 5);
              IF BADTITLE(S) THEN
                EXIT(XECUTE);
              TITLENORM(S, TRUE, 80);
              RESET(EXEC_FILE, S);
              IF IORESULT = 0 THEN
              BEGIN
                NEWEXBUF;
                R_EXEC_FLG := TRUE;
                EXEC_BLK := TRUE;
                EXECREADBLK;
                EXEC_TERM := EXBUFPTR^[EXEC_CH_NUM];
                EXEC_CH_NUM := EXEC_CH_NUM + 1
              END
              ELSE
                EXECOPNERR(2)
            END;
            EXIT(XECUTE)
          END
        END;
        TITLENORM(S, FALSE, 80);
        IF ASSOCIATE(S, FALSE, FALSE, TRUE, DONT_CARE, FALSE) THEN
        BEGIN
          GETCMD := SYSPROG;
          EXIT(GETCMD)
        END
      END
    END;

      call into `.19` hardcodes `RUNONLY`/`ERROR_OK` both `TRUE`
      (`GETCMD.19(@L2, L1, 1, 1, @GATVLEV, 0)`, the two literal `1`s in
      argument positions 3/4), so this specific routine only ever
      handles the "Run" case, always setting `GETCMD := SYSPROG` on
      success -- UCSD's own `DEBUGCALL` branch must live somewhere
      else in the real binary's own call graph (not chased this

    PROCEDURE SWAPMENU;
      VAR
        { CH first, OLDLEV second: the real binary reads the answer
          through `LLA 1` and keeps the level in `2`, and declaration
          groups ascend (finding 93a), so this order is the binary's,
          not a preference. }
        CH: CHAR;
        OLDLEV: INTEGER;
    BEGIN
      OLDLEV := ORD(SWAP_2_ON) + ORD(SWAP_1_ON);
      WRITELN;

      WRITELN;
      WRITE('  0 = system is not swapped');
      WRITELN;
      WRITE('  1 = file open and close procedures are swapped');
      WRITELN;
      WRITE('  2 = file open/close and disk get/put procedures are swapped');
      WRITELN;
      WRITELN;
      WRITE('Old swapping level is ');
      WRITE(OLDLEV);
      WRITELN;

        WRITE(CH);
        SWAP_1_ON := (CH = '2');
        SWAP_2_ON := (CH = '1') OR SWAP_1_ON;
        IF SWAP_1_ON THEN
        BEGIN
          WRITELN;
          WRITELN;
          WRITE('Warning: programs using GET or PUT to disk will be very slow')
        END
      END
    END;
    { `GETCMD.27` -- the writer half: `M(ake exec`. Our own name.
      Prompt for a name, give it an `[8]` size specifier unless the
      user already ended it in `.` or `]`, `REWRITE` it, offer to
      change the terminator from `%`, then open the write buffer and
      lay down two empty blocks so the text file has its own header
      page before any character is put.

      `REWRITE`/`RESET` rather than a written-out `FOPEN` is what the
      fourth argument says: every hand-written `FOPEN` in this file
      passes `NIL` and compiles to `LDCN`, and both of these compile
      to `SLDC 0`. `EXEC_FILE` is a `FILE`, not a `FIB`, so the sugar
      is the only thing that can call `FOPEN` on it at all -- the same
      mechanism `CLOSE(EXEC_FILE)` already uses in `EXECCLOSE`.

      `data=90` is 45 words: `I` at 1, `S` (a `STRING[40]`) at 2,
      `ENDSDOT` at 23, and 22 words of `CONCAT` temporary at 24, which
      is `STRING[43]` -- `SCONCAT`'s running maxima are `40` then
      `43`. The `FOR` limit then reuses word 24 once the concatenation
      is done with it. }
    PROCEDURE NEWEXEC;
      VAR
        I: INTEGER;
        S: STRING[40];
        ENDSDOT: BOOLEAN;
    BEGIN
      WRITE('New exec name:');
      READ(S);
      READLN;
      IF LENGTH(S) > 0 THEN
      BEGIN
        ENDSDOT := S[LENGTH(S)] = '.';
        IF BADTITLE(S) THEN
          EXIT(NEWEXEC);
        TITLENORM(S, TRUE, 37);
        IF (LENGTH(S) > 0) AND NOT ENDSDOT THEN
          IF S[LENGTH(S)] <> ']' THEN
            S := CONCAT(S, '[8]')
      END;
      REWRITE(EXEC_FILE, S);
      IF IORESULT = 0 THEN
      BEGIN
        EXEC_TERM := CHR(37);
        WRITE('Terminator=');
        WRITE(EXEC_TERM);
        WRITE(', change it?');
        IF GETYESNO THEN
        BEGIN
          WRITELN;
          WRITE('New terminator:');
          READ(EXEC_TERM)
        END;
        NEWEXBUF;
        W_EXEC_FLG := TRUE;
        FILLCHAR(EXBUFPTR^, 512, CHR(0));
        EXEC_BLK := FALSE;
        FOR I := 1 TO 2 DO
          IF W_EXEC_FLG THEN
            EXECWRITEBLK;
        IF W_EXEC_FLG THEN
          EXECPUTCH(EXEC_TERM)
      END
      ELSE
        EXECOPNERR(2)
    END;

  { `GETCMD.1` -- the segment body, and the command loop itself. Every
    other procedure in the segment exists for it, which is why it is
    the last one written rather than the first: its `CLP` operands are
    procedure numbers, and a wrong number would have compiled just as
    quietly as a right one until all 26 of them were real.

    `params=6` is three words (a `CMDSTATE` result and `LASTST`) and
    `data=6` is the three the segment already declared, so there is no
    `WITH` anywhere in it and no temporary either -- with a body this
    size that is itself a constraint, and it is what rules out the
    `WITH USERINFO DO` the three `ERRNUM`/`ERRBLK`/`ERRSYM` stores
    would otherwise suggest.

    Two things it settles that nothing else did:

    * The four console `FIBP`s are one declaration group, so they
      reverse: `SWAPFIB` is word `55` and `INPUTFIB` word `58`. The
      opening five statements say so plainly -- `GFILES[0]` takes word
      58 and `GFILES[1]` word 57, and input-then-output is the only
      assignment of those two names that makes sense. `FEOF, FEOLN`
      inside `FIB` is one group too, so `INC 2` off a `FIBP` is
      `FEOF`, not `FEOLN`.

      two-bit field at bit 7, and `USERKIND` only lands there if the
      seven `BOOLEAN`s ahead of it are one reversed group occupying
      bits 6 down to 0 -- so `SLOWTERM` is bit 4, which is what
      `GETCMD.25` needed and had wrong.

    guard in front of it is a 13-element set literal the compiler
    sizes to six words from its own highest member, not to `SET OF

    confirmation rewrites `CH` to `'Z'` on a refusal so the shared arm

    { `FPNEWBLK` = `FILEPROC.2` (finding 168), `FPRESET`'s own nested
      helper -- decoded from its addressed real disassembly. Advances
      `F` past a block boundary: clears `FREPTCNT`/`FEOF`/`FEOLN`,
      then (block-device files only) raises `FMAXBLK` if `FNXTBLK` has
      gone past it, and (soft-buffered files only) flushes a changed
      in-memory buffer to disk via `UNITWRITE` -- zero-padding its tail
      with `FILLCHAR` first when at a fresh high-water block, and (for
      `TEXTFILE`s specifically, at a boundary) writing a second,
      freshly-zeroed block immediately after and bumping `FMAXBLK`
      again. Resets `FNXTBLK` to `0` (or `2`, for a soft-buffered
      `TEXTFILE`) at the end either way. `IORSLT`-style bookkeeping and
      absolute-block arithmetic (`FHEADER.DFIRSTBLK + FNXTBLK`, `-1`
      for the just-finished block vs. none for the new one) mirror the
      same idiom `CANTSTRETCH` already established (finding 165).
      **Exact** since finding 231: the last two instructions were the
      `<> 0` written where Apple wrote `ODD(FNXTBLK)`, the free cast
      described at `FPPEEK` above. }
    PROCEDURE FPNEWBLK(VAR F: FIB);
      VAR
        ATBOUNDARY: BOOLEAN;
    BEGIN
      WITH F DO
      BEGIN
        FREPTCNT := 0;
        FEOLN := FALSE;
        FEOF := FALSE;
        IF FISBLKD THEN
        BEGIN
          ATBOUNDARY := FNXTBLK > FMAXBLK;
          IF ATBOUNDARY THEN
            FMAXBLK := FNXTBLK;
          IF FSOFTBUF THEN
          BEGIN
            IF ATBOUNDARY THEN
              FMAXBYTE := FNXTBYTE
            ELSE
              IF FNXTBLK = FMAXBLK THEN
                IF FNXTBYTE >= FMAXBYTE THEN
                BEGIN
                  ATBOUNDARY := TRUE;
                  FMAXBYTE := FNXTBYTE
                END;
            IF FBUFCHNGD THEN
            BEGIN
              FBUFCHNGD := FALSE;
              FMODIFIED := TRUE;
              IF ATBOUNDARY THEN
                FILLCHAR(FBUFFER[FNXTBYTE], 512 - FNXTBYTE, CHR(0));
              UNITWRITE(FUNIT, FBUFFER[0], 512,
                        (FHEADER.DFIRSTBLK + FNXTBLK) - 1);
              IF ATBOUNDARY AND (FHEADER.DFKIND = TEXTFILE) AND
                 ODD(FNXTBLK) THEN
              BEGIN
                FMAXBLK := FMAXBLK + 1;
                FILLCHAR(FBUFFER[0], 512, CHR(0));
                UNITWRITE(FUNIT, FBUFFER[0], 512,
                          FHEADER.DFIRSTBLK + FNXTBLK)
              END
            END;
            FNXTBYTE := 512
          END;
          FNXTBLK := 0;
          IF FSOFTBUF AND (FHEADER.DFKIND = TEXTFILE) THEN
            FNXTBLK := 2
        END
      END
    END;

    PROCEDURE FPRESET(VAR F: FIB);
    BEGIN
      SYSCOM^.IORSLT := INOERROR;
      WITH F DO
        IF FISOPEN THEN
        BEGIN
          FPNEWBLK(F);
          IF FRECSIZE > 0 THEN
            IF FSTATE = FJANDW THEN
              FGET(F)
            ELSE
              FSTATE := FNEEDCHAR
        END
    END;

        search (finding 175, body written per finding 176). Given a new
        file's name/kind/requested size and the directory to search,
        finds where to put it and inserts the entry via `INSENTRY`,
        returning the chosen index (`0` on failure). Two totally
        different algorithms depending on `FSIZE`'s sign at entry:

        - `FSIZE > 0` (an explicit size, `NAME.CODE[nnn]`): a plain
          first-fit scan over `1..DNUMFILES`, taking the first gap
          (`DFIRSTBLK[i] - DLASTBLK[i-1]`) at least `FSIZE` blocks wide.

          the *two* largest gaps across the whole directory (including
          the gap after the last file, up to the volume's own
          `DEOVBLK`); the final choice is the second-largest gap if
          it's at least half the largest, else half the largest
          (rounded up) -- this project's own `CLAUDE.md` already
          documents this exact algorithm as UCSD's `[*]` file-size
          rule ("reserves the second-largest contiguous area, or half
          the largest, whichever is more"), a real independent
          confirmation that this reading is right, not just plausible.

        A full `DNUMFILES = 77` directory (this project's own
        already-documented 77-file volume cap) forces failure
        (`BESTIDX := 0`) regardless of which path found a candidate.

        `FTID` is a `VAR` parameter -- not a value one -- confirmed by
        a locals-size mismatch: a value `STRING[15]` parameter costs
        the callee an 8-word local shadow copy the real binary's own

        `FOR` loop's limit temp (finding 217's rule), and the loop it

        the two arms is which comes from the `FJP`'s fall-through --

        fixed the declaration order -- a nested procedure reading its

          VAR GAP: INTEGER;
        BEGIN
          GAP := GAPSTART - GAPEND;
          IF GAP > FSIZE THEN
          BEGIN
            SECONDIDX := BESTIDX;
            SECONDSIZE := FSIZE;
            BESTIDX := GAPIDX;
            FSIZE := GAP
          END
          ELSE IF GAP > SECONDSIZE THEN
          BEGIN
            SECONDSIZE := GAP;
            SECONDIDX := GAPIDX
          END
        END;

        BESTIDX := 0;

        SECONDIDX := 0;
        SECONDSIZE := 0;

            FMODIFIED := FALSE;

    { `FPCLOSE` = `FILEPROC.7`, `FCLOSE`'s real target (finding 173),
      decoded from its own addressed disassembly. Guards on the file
      actually being open and not the system terminal (`F.FWINDOW <>
      SYSTERM^.FWINDOW`), then only block-device files (`FISBLKD`) with
      a sane cached header (`LENGTH(DVID) > 0`, the same sanity check
      `CANTSTRETCH` uses) do real work:

      `CCRUNCH` (`FTYPE = 3`) shrinks the file to its current position
      first (`FMAXBLK := FNXTBLK`), marks the header temp (`DACCESS.
      YEAR := 100`, `DATEREC`'s own documented sentinel) and then
      *rewrites its own `FTYPE` parameter to `CLOCK`* (`SLDC 1 |
      STL 1`) -- from here on a crunch close behaves as a lock close,
      which is why every later test reads `0` or `2` and never `3`.
      `FPNEWBLK`
      flushes any pending soft-buffer write. If anything actually
      changed (`FMODIFIED`, the temp mark, or `CPURGE`), re-`VOLSEARCH`
      the file's volume (bailing `ILOSTUNIT` on a unit mismatch, the
      same shape `CANTSTRETCH` established) and re-scan the directory for
      the matching entry by block range (`ILOSTFILE` if not found,
      again matching `CANTSTRETCH`'s own idiom). Then: `CNORMAL` on a
      temp-marked entry, or any `CPURGE`, deletes it outright
      (`DELENTRY`); otherwise `DIRSEARCH`es by *title* for a
      same-named conflicting entry and deletes that one first (with an
      index adjustment if it sat earlier in the directory), decides the
      entry's `DACCESS` date (stamp `THEDATE` if either side was
      temp-marked or the file was genuinely modified with a real
      `THEDATE` available, otherwise keep the directory's own existing
      date unchanged), finalizes `DLASTBLK`/`DLASTBYTE` from the
      relative bookkeeping, clears the modified flag, and writes the
      whole header back with `WRITEDIR`. `CPURGE` with no title clears
      the cached volume ID in `UNITABLE` too, even for non-block files
      (the one piece of work outside the `FISBLKD` guard). Every path
      converges on the same tail: `FEOF`/`FEOLN := TRUE`,
      `FISOPEN := FALSE`.

      Global word 67 (`THEDATE`, "today -- set in FILER or sign-on",
      already declared in this file) confirmed by an isolated probe
      before trusting it, not assumed from the comment alone
      (`probe_thedate_offset.py`, scratch).

      The shape came out of the jump targets, which said four things
      the instruction text alone did not. The `FISOPEN` guard's `FJP`
      goes to the **`RNP`**, not to the tail -- a file that was never
      open leaves `FEOF`/`FEOLN`/`FISOPEN` untouched, so the whole
      body including that tail sits inside the guard. The two `IORSLT`
      failure arms `UJP` *past* the `FTYPE = 2` block to the tail,
      which is a `GOTO 1`, not an `ELSE`. `DELENTRY`'s arm `UJP`s to
      `WRITEDIR`, so the write is a sibling of the `IF`, not the last
      statement of its `ELSE`. And two consecutive `UJP`s at `$0676`/
      `$0678` are finding 215's empty `ELSE` again. The two `data`
      words the earlier reading was missing are the `WITH F DO` and
      `WITH FHEADER DO` pointers -- finding 217's rule.

      Note which references are bare and which are qualified: bare
      `DLASTBYTE` compiles through the inner `WITH` (`SLDL 8 | INC
      11`) while `FHEADER.FILLER2` and `DIR^[I] := FHEADER` name the
      record itself and so go through the *outer* one (`SLDL 7 | INC
      18`, `INC 16`). Both forms are legal and they are not
      interchangeable in the output, so the binary reads the source's
      own punctuation back. `VOLSEARCH` is handed `FVID`, the FIB's
      own volume name, not `FHEADER.DVID`. }
    PROCEDURE FPCLOSE(VAR F: FIB; FTYPE: CLOSETYPE);
      LABEL 1;
      VAR
        I, J: INTEGER;
        DIR: DIRP;
        FOUND: BOOLEAN;
    BEGIN
      SYSCOM^.IORSLT := INOERROR;
      WITH F DO
        IF FISOPEN AND (FWINDOW <> SYSTERM^.FWINDOW) THEN
        BEGIN
          IF FISBLKD THEN
            WITH FHEADER DO
              IF LENGTH(DVID) > 0 THEN
              BEGIN
                IF FTYPE = CCRUNCH THEN
                BEGIN
                  FMAXBLK := FNXTBLK;
                  DACCESS.YEAR := 100;
                  FTYPE := CLOCK;
                  IF FSOFTBUF THEN
                    FMAXBYTE := FNXTBYTE
                END;
                FPNEWBLK(F);
                IF FMODIFIED OR (DACCESS.YEAR = 100)
                   OR (FTYPE = CPURGE) THEN
                BEGIN
                  IF FUNIT <> VOLSEARCH(FVID, FALSE, DIR) THEN
                  BEGIN
                    SYSCOM^.IORSLT := ILOSTUNIT;
                    GOTO 1
                  END;
                  I := 1;
                  FOUND := FALSE;
                  WHILE (I <= DIR^[0].DNUMFILES) AND NOT FOUND DO
                  BEGIN
                    FOUND := (DIR^[I].DFIRSTBLK = DFIRSTBLK) AND
                             (DIR^[I].DLASTBLK = DLASTBLK);
                    I := I + 1
                  END;
                  IF NOT FOUND THEN
                  BEGIN
                    SYSCOM^.IORSLT := ILOSTFILE;
                    GOTO 1
                  END;
                  I := I - 1;
                  IF ((FTYPE = CNORMAL)
                      AND (DIR^[I].DACCESS.YEAR = 100))
                     OR (FTYPE = CPURGE) THEN
                    DELENTRY(I, DIR)
                  ELSE
                  BEGIN
                    J := DIRSEARCH(DTID, TRUE, DIR);
                    IF (J <> 0) AND (J <> I) THEN
                    BEGIN
                      DELENTRY(J, DIR);
                      IF J < I THEN
                        I := I - 1
                    END;
                    IF DIR^[I].DACCESS.YEAR = 100 THEN
                      IF DACCESS.YEAR = 100 THEN
                        DACCESS := THEDATE
                      ELSE
                    ELSE
                      IF FMODIFIED AND (THEDATE.MONTH <> 0) THEN
                        DACCESS := THEDATE
                      ELSE
                        DACCESS := DIR^[I].DACCESS;
                    DLASTBLK := DFIRSTBLK + FMAXBLK;
                    IF FSOFTBUF THEN
                      DLASTBYTE := FMAXBYTE;
                    FHEADER.FILLER2 := 0;

    { `FPTITLE` = `FILEPROC.8`, the file-title normalizer -- what
      `TITLENORM` (`PASCALSY.43`) forwards into and what every
      `CXP 0,43` on the disk set ends up in (finding 219).

      Rewritten whole against Apple's own disassembly (finding 229).
      The version this replaces was written before finding 201 and
      routed every single-character separator through a scratch
      `SEP: STRING`, because `SPOS`'s `TARGET` is a `VAR STRING` and a
      literal will not bind to it (error 154). That was the wrong
      conclusion from a true fact: `POS`/`COPY`/`DELETE`/`CONCAT` are
      *sugar*, the compiler builds their argument lists itself, and no
      VAR-actual check applies to what it builds -- exactly as
      finding 201 established for `WRITE`. Written as `POS(' ', S)` it
      compiles, and it compiles to Apple's own `NOP | LSA ' '`. The
      scratch variable was also the whole of the `data` overshoot.

      `SUFFIX` was backwards, and the call sites say so as loudly as
      the binary does: `SLDL 2 | FJP` falls through to `'.TEXT'` when
      the flag is set, and `STARTCOMPILE` passes `TRUE` for the source
      textfile while `XECUTE` passes `FALSE` for a program it is about
      to run. Renamed `WANTTEXT`, here and in `TITLENORM`'s own
      heading, because "suffix" named the wrong thing twice over.

      Two details are Apple's and not what a rewrite would pick:
      the volume-prefix escape tests only the *last* character for
      `':'` rather than searching the whole title, and `LAST5` is
      initialised by assigning `BRACKET` (just set to `''`) rather
      than by a second literal.

      `data=180` is 90 words: `L` at 4, `P` at 5 (which the `FOR` also
      uses as its counter), `BRACKET` 6-26, `SUFX` 27-29, `LAST5`
      30-32, and 61 words of temporary at 33 -- `STRING[120]`, which
      is what `CONCAT(S, BRACKET)`'s running maxima `80` and `120`
      come to. }
    PROCEDURE FPTITLE(VAR S: STRING; WANTTEXT: BOOLEAN; N: INTEGER);
      VAR
        P, L: INTEGER;
        BRACKET: STRING[40];
        LAST5, SUFX: STRING[5];
    BEGIN
      P := POS(' ', S);
      WHILE P > 0 DO
      BEGIN
        DELETE(S, P, 1);
        P := POS(' ', S)
      END;
      L := LENGTH(S);
      IF L > 0 THEN
        IF S[L] <> '.' THEN
        BEGIN
          BRACKET := '';
          LAST5 := BRACKET;
          P := POS('[', S);
          IF P > 0 THEN
          BEGIN
            L := LENGTH(S) - P + 1;
            BRACKET := COPY(S, P, L);
            DELETE(S, P, L)
          END;
          L := LENGTH(S);
          IF L > 0 THEN
            IF S[L] <> ':' THEN
            BEGIN
              IF WANTTEXT THEN
                SUFX := '.TEXT'
              ELSE
                SUFX := '.CODE';
              FOR P := 1 TO L DO
              BEGIN
                IF S[P] IN ['a'..'z'] THEN
                  S[P] := CHR(ORD(S[P]) - 32);
                IF S[P] < ' ' THEN
                  S[P] := '?'
              END;
              IF L > 5 THEN
                LAST5 := COPY(S, L - 5 + 1, 5);
              IF (LAST5 <> SUFX) AND
                 (L + LENGTH(BRACKET) <= N - 5) THEN
              BEGIN
                MOVELEFT(SUFX[1], S[L + 1], 5);
                S[0] := CHR(L + 5)
              END
            END;
          S := CONCAT(S, BRACKET)
        END
        ELSE
          S[0] := CHR(L - 1)
    END;

    `FWRITESTRING` = `PASCALSY.19`, and Apple threw UCSD's version
    away: II.0 does the padding, the soft-buffer loop and the
    `UNITWRITE` itself, all of which Apple moved into `FWRITEBYTES`
    below, leaving eighteen instructions that just hand the string
    over (finding 208).

    The one open instruction was the second argument (finding 214):

        SLDO 3             -- F
        SLDO 2 SLDC 1 ADI  -- S[1], and this is the interesting one
        SLDO 1             -- RLENG
        SLDO 2 SLDC 0 LDB  -- LENGTH(S)
        CBP 20

    `S[1]` is a component of a *packed* variable, which ISO Pascal
    forbids as a `VAR` actual and Apple's compiler rejects with error
    103 -- `IF GATTR.ACCESS = BYTE THEN ... ERROR(103)`, this repo's
    own `BODYPART.text` line 947. The line above it is the exception:

        IF GATTR.ACCESS = BYTE THEN
          IF LSP = BYTEPTR THEN
            BEGIN GEN0(2(*ADI*)); GATTR.ACCESS := INDRCT; ... END
          ELSE ERROR(103);

    A `BYTEPTR` formal -- spelled **`BYTESTREAM`** in source, and new
    in 1.3 (manual III-4, "BYTESTREAM and WORDSTREAM") -- takes a
    byte-addressed actual and folds base and index into one address
    with `ADI`. That instruction *is* the argument, and it exists
    only because 1.3 added the type: 1.1's `PASCALSY.19` is still
    II.0's whole body, doing its own `UNITWRITE(FUNIT, S[1], RLENG)`,
    which needed no such formal because a CSP takes base and offset
    as two separate pushes (`SLDO 2 | SLDC 1`, no `ADI`).

    The manual's own rule for the other half: "The first character of
    any string passed to BYTESTREAM has index number 1; index number 0
    accesses the string's length byte." `FWRITEBYTES` indexes `A` from
    0, so the caller must pass `S[1]`, not `S`. }
  PROCEDURE FWRITESTRING;
  BEGIN
    IF RLENG <= 0 THEN
      RLENG := LENGTH(S);
    FWRITEBYTES(F, S[1], RLENG, LENGTH(S))
  END;

  { `FWRITEBYTES` = `PASCALSY.20` (finding 208), where the work

    II.0 ancestor, with two changes: the blank padding is an inline
    loop over its own counter rather than a call to `FWRITECHAR`, and

    VAR
      AINX: INTEGER;
      PADS: INTEGER;
  BEGIN
    SYSCOM^.IORSLT := INOERROR;
    WITH F DO
      IF FISOPEN THEN
      BEGIN
        IF RLENG > ALENG THEN
        BEGIN
          PADS := RLENG - ALENG;
          WHILE PADS > 0 DO
          BEGIN
            FWINDOW^[0] := ' ';
            FPUT(F);
            PADS := PADS - 1
          END;
          RLENG := ALENG
        END;
        IF FSOFTBUF THEN
        BEGIN
          AINX := 0;
          WHILE (AINX < RLENG) AND NOT FEOF DO
          BEGIN

            FPUT(F);
            AINX := AINX + 1
          END
        END
        ELSE
          UNITWRITE(FUNIT, A, RLENG, 0)
      END
      ELSE
        SYSCOM^.IORSLT := INOTOPEN
  END;

    LABEL 1;
    VAR
      TARGETCHAR, I, J: INTEGER;
      CANDIDATE: STRING;
  BEGIN
    SPOS := 0;
    IF LENGTH(TARGET) > 0 THEN
    BEGIN
      TARGETCHAR := ORD(TARGET[1]);
      I := 1;
      J := (LENGTH(SRC) - LENGTH(TARGET)) + 1;
      CANDIDATE[0] := CHR(LENGTH(TARGET));

      BEGIN

          GOTO 1
        END;

      END
    END;
  1:
  END;

  { `PASCALSY.54` is `CHECKDEL` (finding 209), UCSD's own name and its
    own routine -- `reference_source/ucsd_ii0/SYSTEM.A.TEXT:58` has the
    ancestor, called from `FREADSTRING` to let a console reader take
    back what the typist just typed. It is a `FUNCTION`, which is why
    `params=10` covers five words for three parameters: two of them
    are the function result at 1..2 (`SRO 1` is `CHECKDEL := ...`, and
    `PASCALSY.49` already showed a `BOOLEAN` result costing the same
    two). `data=4` is two `WITH` pointers and no declared locals at all.

    Apple rewrote II.0's body. II.0 emits `BACKSPACE` characters one at
    a time and guards on `BACKSPACE = CHR(0)`; Apple writes two
    prepared global strings, `DLINE_STR` per erased character of a line
    and `BSPACE_STR` per erased character, and only for characters that
    are actually printable (`IF S[SINX] >= ' '`) -- so a control
    character in the buffer takes no screen position back. It also
    checks the line-delete key first and the character-delete key as
    the `ELSE`, where II.0 tests both.

    Three offsets in here are the reversal rule paying for itself, each
    one a check that could have failed:

      * `CRTCTRL` at `SYSCOM+31`. The record's own fields sum there
        exactly -- `BRKPTS` 4 words, `EXPANSION` 9, `MISCINFO` and
        `CRTTYPE` one each -- and `CRTINFO` then lands at `+37`, which
        is where `FGOTOXY` was already independently measured.
      * `ERASEEOL` as the high byte of `CRTCTRL`'s word 1
        (`INC 1 | SLDC 8 | SLDC 8 | LDP`). `RLF, NDFS, ERASEEOL,
        ERASEEOS, HOME, ESCAPE: CHAR` is one field clause, so it
        reverses: `ESCAPE` takes byte 0 and `ERASEEOL` byte 3. And
        `PUTCRT(2, ERASEEOL)` -- index 2, `ERASEEOL`'s own place in
        declaration order -- is the very call `CLEARLINE`'s body
        further down already makes.
      * `CRTINFO.CHARDEL` at `SYSCOM+43` low byte and
        `CRTINFO.LINEDEL` at `+44` low byte. Same reversal:
        `BADCH, CHARDEL, STOP, BREAK, FLUSH, EOF` puts `EOF` at `+41`
        low and `CHARDEL` at `+43` low; `ALTMODE, LINEDEL` puts
        `LINEDEL` at `+44` low. Both offsets fall out of the
        declaration with nothing left over.

    (One thing this does *not* settle: `WIDTH, HEIGHT: INTEGER` is a
    clause too, so the same rule would put `HEIGHT` at `+37` and
    `WIDTH` at `+38`, where the note on `SYSCOM` above says `WIDTH`.
    `FGOTOXY` clamps both and reads the same either way, so nothing
    here can tell them apart. Left alone rather than renamed on a
    guess.) }
  FUNCTION CHECKDEL(CH: CHAR; VAR SINX: INTEGER;
                    VAR S: STRING): BOOLEAN;
  BEGIN
    CHECKDEL := FALSE;
    WITH SYSCOM^, CRTCTRL DO
      IF CH = CRTINFO.LINEDEL THEN
      BEGIN
        CHECKDEL := TRUE;
        WHILE SINX > 1 DO
        BEGIN
          SINX := SINX - 1;
          IF S[SINX] >= ' ' THEN
            WRITE(DLINE_STR)
        END;
        PUTCRT(2, ERASEEOL)
      END
      ELSE
        IF CH = CRTINFO.CHARDEL THEN
        BEGIN
          CHECKDEL := TRUE;
          IF SINX > 1 THEN
          BEGIN
            SINX := SINX - 1;
            IF S[SINX] >= ' ' THEN
              WRITE(BSPACE_STR)
          END
        END
  END;

  { `FWRITEINT` = `PASCALSY.13` (finding 224) -- UCSD's own body with
    the `-32768` special case rewritten. UCSD negates first and then
    notices `ABS(-32768)` came back negative; 1.3 tests
    `I = -MAXINT - 1` *before* touching `I`, as an `IF`/`ELSE` around
    the sign handling. The constant is not folded: `LDCI 32767 | NGI |
    SLDC 1 | SBI` is four instructions for one compile-time value, so
    it has to be written as an expression, not as `-32768`.

    `S`'s `STRING[10]` is fixed by the `SAS 10`, and the declaration
    order is UCSD's untouched: `COL` at 4 and `POT` at 5 is the
    within-clause reversal of `POT, COL: INTEGER`, and the `FOR`
    limit temp lands past `S` at word 14. }
  PROCEDURE FWRITEINT;
    LABEL 1;
    VAR
      POT, COL: INTEGER;
      CH: CHAR;
      SUPPRESSING: BOOLEAN;
      S: STRING[10];
  BEGIN
    COL := 1;
    S[0] := CHR(10);
    SUPPRESSING := TRUE;
    IF I < 0 THEN
      IF I = -MAXINT - 1 THEN
      BEGIN
        S := '-32768';
        GOTO 1
      END
      ELSE
      BEGIN
        I := ABS(I);
        S[1] := '-';
        COL := 2
      END;
    FOR POT := 4 DOWNTO 0 DO
    BEGIN
      CH := CHR(I DIV IPOT[POT] + ORD('0'));
      IF (CH = '0') AND (POT > 0) AND SUPPRESSING THEN
      ELSE
      BEGIN
        SUPPRESSING := FALSE;
        S[COL] := CH;
        COL := COL + 1;
        IF CH <> '0' THEN
          I := I MOD IPOT[POT]
      END
    END;
    S[0] := CHR(COL - 1);
  1:
    IF RLENG < LENGTH(S) THEN
      RLENG := LENGTH(S);
    FWRITESTRING(F, S, RLENG)
  END;

  FUNCTION FBLOCKIO;
    PROCEDURE BLKXFER(UNITNO: INTEGER; VAR BUFADDR: WINDOW; BYTEOFS: INTEGER;
                          NBLOCKS: INTEGER; BLOCKNUM: INTEGER; DOREAD: BOOLEAN);
      VAR
        NB, LEN: INTEGER;
    BEGIN
      IF NBLOCKS > 63 THEN NB := 63 ELSE NB := NBLOCKS;
      LEN := NB * 512;
      WHILE NBLOCKS <> 0 DO
      BEGIN
        IF DOREAD THEN
          UNITREAD(UNITNO, BUFADDR[BYTEOFS], LEN, BLOCKNUM)
        ELSE
          UNITWRITE(UNITNO, BUFADDR[BYTEOFS], LEN, BLOCKNUM);
        IF IORESULT <> 0 THEN EXIT(BLKXFER);
        NBLOCKS := NBLOCKS - NB;
        BYTEOFS := BYTEOFS + LEN;
        BLOCKNUM := BLOCKNUM + NB;
        { Apple's `FJP >+7` covers both statements, not just the
          first: when NBLOCKS is still >= NB the loop leaves LEN alone,
          because NB did not change and LEN is already NB*512. Written
          with `LEN := NB * 512` outside the IF it is the same six
          instructions in the same order and the jump is `>+3`, which is
          what the old comparison could not see (finding 252). }
        IF NBLOCKS < NB THEN
        BEGIN
          NB := NBLOCKS;
          LEN := NB * 512
        END
      END
    END;
  BEGIN
    FBLOCKIO := 0;
    SYSCOM^.IORSLT := INOERROR;
    WITH F DO
      IF FISOPEN AND (NBLOCKS >= 0) THEN
        IF FISBLKD THEN
          WITH FHEADER DO
          BEGIN
            IF RBLOCK < 0 THEN
              RBLOCK := FNXTBLK;
            RBLOCK := DFIRSTBLK + RBLOCK;
            IF RBLOCK + NBLOCKS > DLASTBLK THEN
              IF NOT DOREAD THEN
                IF CANTSTRETCH(F) THEN ;
            IF RBLOCK + NBLOCKS > DLASTBLK THEN
              NBLOCKS := DLASTBLK - RBLOCK;
            FEOF := RBLOCK >= DLASTBLK;
            IF NOT FEOF THEN
            BEGIN
              BLKXFER(FUNIT, A, I, NBLOCKS, RBLOCK, DOREAD);
              IF IORESULT = 0 THEN
              BEGIN
                IF NOT DOREAD THEN
                  FMODIFIED := TRUE;
                FBLOCKIO := NBLOCKS;
                RBLOCK := RBLOCK + NBLOCKS;
                FEOF := RBLOCK = DLASTBLK;
                FNXTBLK := RBLOCK - DFIRSTBLK;
                IF FNXTBLK > FMAXBLK THEN
                  FMAXBLK := FNXTBLK
              END
            END
          END
        ELSE
        BEGIN
          FBLOCKIO := NBLOCKS;
          BLKXFER(FUNIT, A, I, NBLOCKS, RBLOCK, DOREAD);
          IF IORESULT = 0 THEN
            IF DOREAD THEN
            BEGIN
              RBLOCK := NBLOCKS * 512;
              RBLOCK := RBLOCK + SCAN(-RBLOCK, <>CHR(0), A[I + RBLOCK - 1]);
              RBLOCK := (RBLOCK + 512 - 1) DIV 512;
              FBLOCKIO := RBLOCK;
              FEOF := RBLOCK < NBLOCKS
            END
            ELSE
          ELSE
            FBLOCKIO := 0
        END
      ELSE
        SYSCOM^.IORSLT := INOTOPEN
  END;

  BEGIN
    WITH SYSCOM^.CRTINFO DO
    BEGIN
      IF X < 0 THEN
        X := 0;

  { `VOLSEARCH` = `PASCALSY.30` (finding 187). Finds the unit holding
    volume `FVID`, sets `FDIR` to its directory (`NIL` for a non-block
    device -- a valid, deliberate outcome `FPOPEN` already handles,
    findings 182/183), and returns the unit number (`0` if not found).
    Calls into `FETCHDIR` (`PASCALSY.42`, `FUNCTION FETCHDIR(FUNIT:
    UNITNUM): BOOLEAN`, still a stub) to actually read a directory off
    disk -- `FETCHDIR` is its own ~234-instruction routine, comparable
    in size to `VOLSEARCH` itself, and is the next real target, not
    attempted this session.

    Three phases, all gated behind `LENGTH(FVID) > 0` (an empty title
    finds nothing by name, only by the `LOOKHARD` fallback below):

    1. **Parse a `"#nn"` unit-number reference.** `FVID[1] = '#'`
       (`CHR(35)`) with a real digit run after it (`IN DIGITS`, this
       file's own already-declared `SET OF '0'..'9'` global) parses
       straight to a unit number, valid only for `1..20` -- confirming
       `MAXUNIT = 20`, a real fact this project didn't have pinned down
       before. A valid `"#nn"` forces `LOOKHARD` off (no need for the
       thorough fallback once the caller named an exact unit).
    2. **Otherwise, a plain named search**: units `20` downto `1`,
       first match on `UNITABLE[unit].UVID = FVID` wins.
    3. Whichever found a candidate unit, block-structured units get
       verified/fetched: if `SYSCOM^.GDIRP` is already caching *this*
       volume's directory and was loaded within the last `300` ticks
       (the same freshness idiom `WRITEDIR` already established,
       finding 186), trust it outright; otherwise call `FETCHDIR`, and
       -- only for a name-matched unit, not a `"#nn"` one, which
       doesn't need it -- re-verify the fetched directory's own `DVID`
       against `FVID`.

    If nothing panned out and `LOOKHARD` is still set, a *fourth*
    pass -- units `20` downto `1` again, this time unconditionally
    calling `FETCHDIR` on every block-structured one and comparing its
    freshly-read `DVID` -- catches a volume `UNITABLE`'s own cached
    name doesn't yet know about. On any success: the result unit
    number, `FVID` updated to the real matched name (fills in the
    actual name for a `"#nn"` lookup), `FDIR := SYSCOM^.GDIRP` for a
    block device, and a `TIME`-based restamp of `FDIR^[0].DLOADTIME`
    closing the freshness loop for next time.

    Rewritten off Apple's own 245 instructions (finding 215). The
    frame is five declared words plus one for the `WITH`s, and the
    reversal rule places them with nothing left over: `UNITNO` alone
    (6), then `FOUND, UNITBYNUM` (7 and 8 descending), then
    `I, LOTIME` (9 and 10). Two of those do double duty, and that is
    Apple's economy, not a guess -- offset 6 holds both the parsed
    `"#nn"` number and the unit index, offset 8 is the *only* boolean
    besides `UNITBYNUM` and serves as the digit-run flag, `FOUND` and
    the directory-freshness flag in turn, and offset 10 is both the
    parse loop's index and the high word `TIME` writes and nothing
    reads. An earlier version declared `FRESH` and `NUM` separately
    and came out four words too long, which was the tell.

    Three shape corrections came with it: both search loops are
    `REPEAT`, not `WHILE` (the file's own habit, and the fifth and
    sixth instance of it); the digit accumulator is
    `UNITNO * 10 + ORD(FVID[I]) - 48` with no inner parentheses,
    since Apple's `ADI` precedes its `SBI`; and a valid `"#nn"` does
    not assign anything -- it simply leaves `UNITNO` and `FOUND` as
    the parse left them and skips the named search, which is why
    there is no `IF UNITBYNUM THEN BEGIN UNITNO := NUM; ... END`
    anywhere. Three `WITH`s share the one pointer word: `SYSCOM^`
    over the freshness/fetch block, and `UNITABLE[UNITNO]` over each
    of the last two. }
  FUNCTION VOLSEARCH;
    VAR
      UNITNO: UNITNUM;         { and the parsed "#nn" number too      }
      FOUND, UNITBYNUM: BOOLEAN;
      I, LOTIME: INTEGER;      { I doubles as TIME's high word        }
  BEGIN
    VOLSEARCH := 0;
    FDIR := NIL;
    FOUND := FALSE;
    UNITBYNUM := FALSE;
    IF LENGTH(FVID) > 0 THEN
    BEGIN
      IF (FVID[1] = '#') AND (LENGTH(FVID) > 1) THEN
      BEGIN
        FOUND := TRUE;
        UNITNO := 0;
        I := 2;
        REPEAT
          IF FVID[I] IN DIGITS THEN
            UNITNO := UNITNO * 10 + ORD(FVID[I]) - 48
          ELSE
            FOUND := FALSE;
          I := I + 1
        UNTIL (I > LENGTH(FVID)) OR NOT FOUND;
        UNITBYNUM := FOUND AND (UNITNO > 0) AND (UNITNO <= 20);
        LOOKHARD := LOOKHARD AND NOT UNITBYNUM
      END;
      IF NOT UNITBYNUM THEN
      BEGIN
        FOUND := FALSE;
        UNITNO := 20;
        REPEAT
          FOUND := FVID = UNITABLE[UNITNO].UVID;
          IF NOT FOUND THEN
            UNITNO := UNITNO - 1
        UNTIL FOUND OR (UNITNO = 0)
      END
    END;

    IF FOUND THEN
      IF UNITABLE[UNITNO].UISBLKD THEN
        WITH SYSCOM^ DO
        BEGIN
          FOUND := FALSE;
          IF GDIRP <> NIL THEN
            IF FVID = GDIRP^[0].DVID THEN
            BEGIN
              TIME(I, LOTIME);
              FOUND := (LOTIME - GDIRP^[0].DLOADTIME) <= 300
            END;
          IF NOT FOUND THEN
          BEGIN
            FOUND := UNITBYNUM;
            IF FETCHDIR(UNITNO) THEN
              IF NOT UNITBYNUM THEN
                FOUND := FVID = GDIRP^[0].DVID
              ELSE
            ELSE
              FOUND := IORESULT = 0
          END
        END;

    IF (NOT FOUND) AND LOOKHARD THEN
    BEGIN
      UNITNO := 20;
      REPEAT
        WITH UNITABLE[UNITNO] DO
          IF UISBLKD THEN
            IF FETCHDIR(UNITNO) THEN

  { `WRITEDIR` = `PASCALSY.31` (finding 186). Writes `FDIR^` back to
    `FUNIT`'s own directory block, but only after a chain of sanity
    checks -- and always ends by invalidating `UNITABLE[FUNIT]`'s own
    cached volume ID/end-block if any of them failed, forcing a fresh
    `VOLSEARCH` next time rather than trusting a stale cache:

    First, `UNITABLE[FUNIT].UVID` must still match `FDIR^[0].DVID`
    (this file's own already-established volume-consistency idiom),
    and `FDIR^[0]`'s own tag must be `UNTYPEDFILE` or `SECUREDIR` --
    the two `DIRENTRY` variants `DIR[0]`, the volume-info pseudo-entry,
    is ever tagged as. If a write happened *very* recently (`<= 300`
    ticks by `TIME`, this file's own `CSP 9`) with interrupts disabled
    (`SYSCOM^.MISCINFO.NOBREAK`), nothing else could plausibly have
    changed the volume in between, so the paranoid re-check below is
    skipped outright. That third conjunct is `HASCLOCK`, not
    `NOBREAK`: Apple reads bit 0 of `MISCINFO`, which the field
    group's own reversal makes the *last* of the seven booleans, and
    it is the reading the code wants anyway -- a `TIME` comparison
    says nothing on a machine with no clock. The offsets caught a
    semantic error, not just a spelling.

    Otherwise: re-read block `2` (the directory's own
    disk location) into a scratch `DIRENTRY` and compare *its* `DVID`
    against `FDIR^[0]`'s -- confirming the directory this process has
    cached in memory really still belongs to what's physically on the
    unit before overwriting it (a real `IORESULT` failure on that read
    counts as "no match" too).

    fields are otherwise unused by the volume-info variant, but this
    keeps it a known value), `UNITWRITE` the real directory contents
    -- `(DNUMFILES + 1) * 26` bytes, `DIRENTRY`'s own already-
    established 26-byte size times one more than the file count for
    `DIR[0]` itself -- to block `2`. `DIR[0].DLASTBLK = 10` (an
    otherwise-unused field on this variant, repurposed as a flag) marks
    a hard-disk-class volume needing a *second*, redundant copy written
    to block `6` too -- a 128K-ProFile-specific feature, the same
    project theme `PRINTERROR`'s own 128K-specific error codes already
    established (finding 137). On success, `TIME` re-stamps
    `FDIR^[0].DLOADTIME` to now, closing the loop with the "was this
    written very recently" fast-path check above.

    The two missing `data` words are `WITH UNITABLE[FUNIT], FDIR^[0]
    DO`, one pointer each, spanning the whole body -- finding 217's
    rule. Two smaller things came from the bytes as well: the failed
    re-read has no `ELSE OK := FALSE` (it is already `FALSE` there,
    and Apple does not write it), and the invalidating store is the
    *empty* string, not seven spaces. }
  PROCEDURE WRITEDIR;
    VAR
      HITIME, LOTIME: INTEGER;
      OK: BOOLEAN;
      BACKUP: DIRENTRY;
  BEGIN
    WITH UNITABLE[FUNIT], FDIR^[0] DO
    BEGIN
      OK := (UVID = DVID) AND
            ((DFKIND = UNTYPEDFILE) OR (DFKIND = SECUREDIR));
      IF OK THEN
      BEGIN
        TIME(HITIME, LOTIME);
        OK := (LOTIME - DLOADTIME <= 300) AND
              (LOTIME - DLOADTIME >= 0) AND
              SYSCOM^.MISCINFO.HASCLOCK;
        IF NOT OK THEN
        BEGIN
          UNITREAD(FUNIT, BACKUP, 26, 2);
          IF IORESULT = 0 THEN
            OK := DVID = BACKUP.DVID
        END;
        IF OK THEN
        BEGIN
          DFIRSTBLK := 0;
          UNITWRITE(FUNIT, FDIR^, (DNUMFILES + 1) * 26, 2);
          OK := IORESULT = 0;
          IF DLASTBLK = 10 THEN
            UNITWRITE(FUNIT, FDIR^, (DNUMFILES + 1) * 26, 6);
          IF OK THEN
            TIME(HITIME, DLOADTIME)
        END
      END;
      IF NOT OK THEN
      BEGIN
        UVID := '';
        UEOVBLK := 32767
      END
    END
  END;

  FUNCTION SCANTITLE;
    VAR
      I, P: INTEGER;
      CH: CHAR;
      OK: BOOLEAN;
  BEGIN
    FVID := '';
    FTID := '';
    FSEGS := 0;
    FKIND := UNTYPEDFILE;
    SCANTITLE := FALSE;

    I := 1;
    WHILE I <= LENGTH(FTITLE) DO
    BEGIN
      CH := FTITLE[I];
      IF CH <= ' ' THEN
        DELETE(FTITLE, I, 1)
      ELSE
      BEGIN
        IF (CH >= 'a') AND (CH <= 'z') THEN
          FTITLE[I] := CHR(ORD(CH) - ORD('a') + ORD('A'));
        I := I + 1
      END
    END;

    IF LENGTH(FTITLE) > 0 THEN
    BEGIN
      IF FTITLE[1] = '*' THEN
      BEGIN
        FVID := SYVID;
        DELETE(FTITLE, 1, 1)
      END
      ELSE IF FTITLE[1] = '%' THEN
      BEGIN
        FVID := RUN_VOL;
        DELETE(FTITLE, 1, 1)
      END;

      I := POS(':', FTITLE);
      IF I <= 1 THEN
      BEGIN
        IF LENGTH(FVID) = 0 THEN
          FVID := DKVID;
        IF I = 1 THEN
          DELETE(FTITLE, 1, 1)
      END
      ELSE IF (I - 1) <= 7 THEN
      BEGIN
        FVID := COPY(FTITLE, 1, I - 1);
        DELETE(FTITLE, 1, I)
      END;

      IF LENGTH(FVID) > 0 THEN
      BEGIN
        I := POS('[', FTITLE);
        IF I > 0 THEN
          I := I - 1
        ELSE
          I := LENGTH(FTITLE);
        IF I <= 15 THEN
        BEGIN
          IF I > 0 THEN
          BEGIN
            FTID := COPY(FTITLE, 1, I);
            DELETE(FTITLE, 1, I)
          END;
          IF LENGTH(FTITLE) = 0 THEN
            OK := TRUE
          ELSE
          BEGIN
            OK := FALSE;
            P := POS(']', FTITLE);
            IF P = 2 THEN
              OK := TRUE
            ELSE IF P > 2 THEN
            BEGIN
              OK := TRUE;
              I := 2;
              REPEAT
                CH := FTITLE[I];

                BEGIN

                  OK := TRUE
                END
            END
          END;

            `LENGTH(FTITLE) = 0` arm goes to this assignment, not to the
            procedure's exit. Nested inside the ELSE, as this was, a bare

          SCANTITLE := OK;

            ELSE IF FTITLE = '.CODE' THEN

            ELSE IF FTITLE = '.BACK' THEN

              FKIND := GRAFFILE

          END
        END
      END
    END

    now-vacated last slot's `DTID` (the real binary reads `DNUMFILES`
    fresh a second time for this, not the pre-decrement value cached
    in `LAST` -- reproduced literally, not simplified to reusing
    `LAST + 1`) and decrements `DNUMFILES`. `FPOPEN` calls this when a

    VAR I: DIRRANGE;

    END
  END;

  FUNCTION FETCHDIR;
    VAR
      I: DIRRANGE;
      OK: BOOLEAN;
      HITIME: INTEGER;
  BEGIN
    FETCHDIR := FALSE;
    WITH SYSCOM^, UNITABLE[FUNIT] DO
    BEGIN
      IF GDIRP = NIL THEN
        NEW(GDIRP);
      UNITREAD(FUNIT, GDIRP^, 2028, 2);
      OK := IORSLT = INOERROR;
      IF OK THEN
        WITH GDIRP^[0] DO
        BEGIN
          OK := FALSE;
          IF (DFIRSTBLK = 0) AND
             ((MISCINFO.USERKIND = BOOKER) OR
              ((MISCINFO.USERKIND IN [AQUIZ, PQUIZ]) AND
               (DFKIND = SECUREDIR)) OR
              ((MISCINFO.USERKIND = NORMAL) AND
               (DFKIND = UNTYPEDFILE))) THEN
            IF (LENGTH(DVID) > 0) AND (LENGTH(DVID) <= 7) AND
               (DNUMFILES >= 0) AND (DNUMFILES <= 77) THEN
            BEGIN
              OK := TRUE;
              IF DVID <> UVID THEN
              BEGIN
                I := 1;
                WHILE I <= DNUMFILES DO
                  WITH GDIRP^[I] DO
                    IF (LENGTH(DTID) <= 0) OR (LENGTH(DTID) > 15) OR
                       (DLASTBLK < DFIRSTBLK) OR
                       (DLASTBYTE > 512) OR (DLASTBYTE <= 0) OR
                       (DACCESS.YEAR >= 100) THEN
                    BEGIN
                      OK := FALSE;
                      DELENTRY(I, GDIRP)
                    END
                    ELSE
                      I := I + 1;
                IF NOT OK THEN
                BEGIN
                  UNITWRITE(FUNIT, GDIRP^, (DNUMFILES + 1) * 26, 2);
                  OK := IORSLT = INOERROR
                END
              END
            END;
          IF OK THEN
          BEGIN
            UVID := DVID;
            UEOVBLK := DEOVBLK;
            TIME(HITIME, DLOADTIME)
          END
        END;
      FETCHDIR := OK;
      IF NOT OK THEN
      BEGIN
        UVID := '';
        UEOVBLK := 32767;
        RELEASE(GDIRP);
        GDIRP := NIL
      END
    END
  END;

    `GETNEXTCMD`: while `SWAP_ON`, waits for the system volume and
    reads a command via `GETCMD`; a real command (`STATE >=
    UPROGNOU`) either launches `USERPROGRAM` (when `SWAP_2_ON` and

    Either way, a real command also clears the swap flag, resets unit
    `3`, and re-verifies the boot unit's own directory (`FETCHDIR`,
    result intentionally discarded -- the real binary's own bare
    boolean-statement shape this host compiler won't accept directly,
    same class of divergence as elsewhere in this file). A just-
    finished compile-only command (`COMPONLY`/`COMPANDGO`/

    files. Finally, if either console unit is busy, it gets cleared.

    PROCEDURE GETNEXTCMD;
      VAR IORSLT: INTEGER;
    BEGIN (*$R FILEPROC*)
      REPEAT
        IF NOT SWAP_ON THEN
        BEGIN
          WAITSYSVOL;
          STATE := GETCMD(STATE);
          CHAIN_NAME := '';
          CASE STATE OF
            UPROGNOU, UPROGUOK, SYSPROG, COMPONLY, COMPANDGO,
            COMPDEBUG, LINKANDGO, LINKDEBUG, CMDST10:
              IF NOT SWAP_2_ON OR WHAT_H1 THEN
              BEGIN
                WHAT_H1 := FALSE;
                USERPROGRAM(NIL, NIL)
              END
              ELSE
              BEGIN
                SWAP_ON := TRUE;
                EXIT(GETNEXTCMD)
              END
          END
        END;
        IF STATE IN [UPROGNOU..CMDST10] THEN
        BEGIN
          SWAP_ON := FALSE;
          UNITCLEAR(3);
          IF FETCHDIR(SYSCOM^.SYSUNIT) THEN ;
        END;
        IF STATE IN [COMPONLY..COMPDEBUG] THEN
          IF USERINFO.ERRNUM = 0 THEN
          BEGIN
            FCLOSE(USERINFO.CODEFIBP^, CLOCK);
            IF IORESULT <> 0 THEN
            BEGIN
              IORSLT := IORESULT;
              WRITELN;
              CLEARLINE;
              PRINTERROR(10, IORSLT)
            END
          END;
        IF STATE IN [UPROGNOU, UPROGUOK] THEN
        BEGIN
          FCLOSE(GFILES[0]^, CNORMAL);
          FCLOSE(GFILES[1]^, CLOCK)
        END;
        IF UNITBUSY(1) OR UNITBUSY(2) THEN
          UNITCLEAR(1)
      UNTIL STATE = HALTINIT
    END;

      compiler emits `LOADSEGMENT(2)` in the entry stub and
      `UNLOADSEGMENT(2)` in the exit code, which is the six-instruction
      wrapper the real `PASCALSY.58` carries and nothing else here
      could produce. The directive is a VERIFIED SOURCE FACT, not a
      guess -- this project's own byte-identical `SYSTEM.COMPILER`
      reconstruction uses exactly it, `BEGIN (*$R ROUTINE*) BODY END`

    PROCEDURE CMDDISPATCH;
    BEGIN (*$R 2*)
      REPEAT
        WAITSYSVOL;
        GETNEXTCMD;
        IF (NOT SWAP_1_ON) AND SWAP_ON THEN
          USERPROGRAM(NIL, NIL)
        ELSE
          EXIT(CMDDISPATCH)
      UNTIL STATE = HALTINIT
    END;

  BEGIN
    STATE := HALTINIT;
    SWAP_ON := FALSE;
    REPEAT
      WAITSYSVOL;
      CMDDISPATCH;
      IF SWAP_ON THEN
        USERPROGRAM(NIL, NIL)
    UNTIL STATE = HALTINIT
  END;
  { `CANTSTRETCH`'s real body (finding 165), decoded from `PASCALSY.49`'s
    addressed disassembly using `DIRENTRY`'s probe-verified offsets
    (finding 164). Attempts to extend `F`'s file allocation on disk:
    verifies `F.FHEADER.DVID` is non-empty, `VOLSEARCH`es for the
    file's own volume and checks it landed on the same unit
    (`SYSCOM^.IORSLT := ILOSTUNIT` if not -- `IORSLTWD`'s own value 5),
    scans the fetched directory for the entry matching `F`'s cached
    header by `DFIRSTBLK`/`DLASTBLK` (`ILOSTFILE`, value 6, if not
    found), computes the extension boundary (the next file's own
    `DFIRSTBLK`, or the volume's `DEOVBLK` if this is the last entry),
    and either reports no extension was needed (result stays `TRUE`)
    or extends the entry, writes the directory back via `WRITEDIR`,
    and on success updates `F`'s own cached fields to match (clearing
    `FEOF`/`FEOLN`, `FSTATE`, and stamping `DACCESS.YEAR := 100` --
    `DATEREC`'s own documented "temp-disk flag" sentinel) before
    returning `FALSE`. **Exact** since finding 215; four things had to
    change and each was read off the addressed disassembly:

      * The `WITH F DO WITH FHEADER DO` pair opens the whole body,
        ahead of the `LENGTH(DVID) > 0` guard, so both pointer words
        (9 and 10) are live before the first test. Every later field
        then picks its own `WITH`: bare `FEOF` is `SLDO 9 | INC 2`
        because `DIRENTRY` has no such field, bare `DLASTBLK` is
        `SLDO 10 | INC 1` because `FHEADER` does.
      * `VOLSEARCH`'s first argument is `FVID` (`F` word 8), not
        `FHEADER.DVID` (word 19) -- the FIB's own cached volume name,
        not the directory entry's copy. And the comparison reads
        `FUNIT <> VOLSEARCH(...)`, unit first.
      * The extend test runs its body when the condition is **true**
        (`(DLASTBLK < NEWLAST) OR (DLASTBYTE < 512)` means there is
        room), with `DONE := TRUE` following the whole `IF` rather
        than sitting in a branch of it. An earlier reading had the
        branches swapped, which compiles to the same expression and a
        different shape.
      * `IF IORESULT <> 0 THEN GOTO 1` -- a real `GOTO` past
        `DONE := TRUE` to the tail, which is why `DONE` is left
        `FALSE` on a failed `WRITEDIR` and the tail reads
        `IF NOT DONE`, not `IF DONE`. No `IF`/`ELSE` nesting can jump
        out of two levels *and* past a following statement, so the
        label is not optional: it is what the two `UJP`s to the same
        address say.

    `FOUND, DONE: BOOLEAN` in that order, since one clause descends:
    `DONE` at 5, `FOUND` at 6. }
  FUNCTION CANTSTRETCH;
    LABEL 1;
    VAR
      I: INTEGER;
      FOUND, DONE: BOOLEAN;
      NEWLAST: INTEGER;
      DIR: DIRP;
  BEGIN
    CANTSTRETCH := TRUE;
    DONE := FALSE;
    WITH F DO
      WITH FHEADER DO
        { `GOTO 1` on both failures, as UCSD's `CANTSTRETCH` has it,
          not an `ELSE` (finding 282). The code is the same either way.
          The difference is which label resolves last. `ILOSTUNIT`'s jump
          to `1:` is too long for a byte, so it goes through the jump
          table, and a slot is handed out when its label is placed. An
          `ELSE` skip is placed before the outer `IF`'s exit, and user
          label `1` after it. Apple's slots are in the second order. The
          `ILOSTFILE` jump is short and so shows nothing either way. }
        IF LENGTH(DVID) > 0 THEN
        BEGIN
          IF FUNIT <> VOLSEARCH(FVID, FALSE, DIR) THEN
          BEGIN
            SYSCOM^.IORSLT := ILOSTUNIT;
            GOTO 1
          END;
          FOUND := FALSE;
          I := 1;
          WHILE (I <= DIR^[0].DNUMFILES) AND NOT FOUND DO
          BEGIN
            FOUND := (DIR^[I].DFIRSTBLK = DFIRSTBLK) AND
                     (DIR^[I].DLASTBLK = DLASTBLK);
            I := I + 1
          END;
          IF NOT FOUND THEN
          BEGIN
            SYSCOM^.IORSLT := ILOSTFILE;
            GOTO 1
          END;
          IF I > DIR^[0].DNUMFILES THEN
            NEWLAST := DIR^[0].DEOVBLK
          ELSE
            NEWLAST := DIR^[I].DFIRSTBLK;
          IF (DLASTBLK < NEWLAST) OR (DLASTBYTE < 512) THEN
          BEGIN
            WITH DIR^[I - 1] DO
            BEGIN
              DLASTBLK := NEWLAST;
              DLASTBYTE := 512
            END;
            WRITEDIR(FUNIT, DIR);
            IF IORESULT <> 0 THEN
              GOTO 1;
            FEOF := FALSE;
            FEOLN := FALSE;
            IF FSTATE <> FJANDW THEN
              FSTATE := FNEEDCHAR;
            DLASTBLK := NEWLAST;
            DLASTBYTE := 512;
            DACCESS.YEAR := 100;
            CANTSTRETCH := FALSE
          END;
          DONE := TRUE
        END;
  1:
    IF NOT DONE THEN
    BEGIN
      F.FEOF := TRUE;
      F.FEOLN := TRUE
    END
  END;

  PROCEDURE WAITSYSVOL;
  VAR
    { One word Apple's own frame has and this procedure never touches.
      It is not a size fudge: the real body reads its character through
      `LAO 2`, so something occupies offset 1 ahead of it, and `data=4`
      says that something is one word wide. The name is not recoverable
      -- names never are -- so it is declared and left unused, which is
      exactly what the binary shows. }
    UNUSED1: INTEGER;
    DUMMY: CHAR;
  BEGIN
    RELEASE(EMPTYHEAP);
    WHILE UNITABLE[SYSCOM^.SYSUNIT].UVID <> SYVID DO
    BEGIN
      PL := 'Put in :';
      INSERT(SYVID, PL, 8);
      PROMPT;
      WRITELN;
      CLEARLINE;
      WRITE('then press RETURN');
      REPEAT
        READ(KEYBOARD, DUMMY)
      UNTIL EOLN(KEYBOARD);
      IF FETCHDIR(SYSCOM^.SYSUNIT) THEN
      BEGIN
      END
    END
  END;
